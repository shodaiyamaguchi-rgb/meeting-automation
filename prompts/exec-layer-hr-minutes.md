# B-3　経営レイヤー定例【人事版】：会議後の議事録生成とSlack投稿

対象会議：`exec-layer-hr`（経営レイヤー定例【人事版】）
実行タイミング：会議終了の1時間後（火曜16:00）／翌日12:00のリトライ

**このあと、続けて A-3（`prompts/exec-layer-hr-prep.md`：次回分のページ作成）を実行する。** A-3 は、この処理が書き込んだ 0. の持ち帰り表（進捗・ステータス）を次回ページへ写すため、必ずこの処理のあとに動く。この処理はそこまで関知せず、本文の手順どおり終えればよい。

経営レイヤー定例【人事版】の議事録を作成し、Slackへ展開してください。**対象日**（実行時コンテキストの `TARGET_DATE`）に開催された回が対象です。

## 事業版（B-2）との違い

この処理は `prompts/exec-layer-minutes.md`（事業版）と同じ骨格だが、次の4点が違う。**事業版のプロンプトを読んで代用しないこと。**

| | 事業版（exec-layer） | 人事版（exec-layer-hr） |
|---|---|---|
| カレンダーの予定名 | 経営レイヤー定例（事業編）mtg | **経営レイヤーmtg（人事系）**（「定例」が入らない） |
| 議事録DB | `collection://232b1cc0-…` | **`collection://27870844-f19e…`**（config の `minutes_data_source_url` を使う） |
| ページタイトル | `YYYY-MM-DD 経営レイヤー定例` | **`YYYY-MM-DD 経営レイヤー定例（人事版）`** |
| ⏺️ 文字起こし（自動要約） | 埋めない | **埋める**（手順3-3） |

アジェンダが 0・1・4 の3つであること、ステータスが `事前記入中` / `記録済` / `確認済` の3つであることは事業版と同じ。**このDBにも「自動生成済」は存在しない。**

## 手順

### 1. 文字起こしを取得する

1. Google Calendar の `list_events` で、対象日（00:00〜23:59 JST）の予定を取得する。タイトルが `calendar_title_keywords` の**いずれか1つ**を含む予定を探す。`calendar_title_exclude` に一致するものは除く（事業版の回を拾わないため）。

   **人事版の予定名には「定例」が入らない。** 事業版の `経営レイヤー定例` では一致しないので、1つのキーワードで決め打ちしない。
2. 予定が見つからない場合は、**その旨だけ報告して終了する。** Notionには何も書かない。
3. 予定の `attachments` から「Gemini によるメモ」（Google Docs）を探す。要約と逐語の文字起こしが1つのドキュメントに入っている。`… Recording`（動画）は使わない。
4. 添付が見つからない場合は、Google Drive の `search_files` でフォールバックする。

   ```
   title contains '経営レイヤー' and modifiedTime > '{{対象日}}T00:00:00+09:00'
   ```

   ヒットしたドキュメントが**人事版の回のものか**をタイトルの日付・時刻（14:59 など）で確かめる。同じ日に事業版の回はないが、週をまたいで古いものを拾わないこと。
5. `read_file_content` で本文を取得する。**文字起こしがまだ生成されていない場合は、その旨だけ報告して終了する。** 翌日のリトライで再実行される。
6. ドキュメントのURLを控える（あとでプロパティに入れる）。

### 2. Notionの対象ページを取得する

1. 対象日のページを探す。**まず `notion-search` を使う。**

   ```
   notion-search: query="経営レイヤー定例 人事版 議事録",
                  data_source_url="collection://27870844-f19e-…"（config の値）
   ```

   タイトルが `YYYY-MM-DD 経営レイヤー定例（人事版）` の形で対象日と一致するページを選ぶ。`【雛形】` で始まるページは対象外。**雛形には絶対に書き込まない。**

   **事業版のDBを引かないこと。** タイトルが似ているため、`data_source_url` を必ず指定する。
2. ページが見つからない場合は、**新規作成せず、その旨を報告して終了する。** ページの作成は A-3 の責務。
3. ステータスが `記録済` または `確認済` なら、**二重実行を避けて終了する。** 対象は `事前記入中` のページのみ。
4. `notion-fetch` でページ本文を取得する。以降の置換に使うので、取得した本文はそのまま保持しておく。
5. 🟩 共有しておきたいこと、各アジェンダの 🟩 事前記入、0. の「🟦 前回の持ち帰り（自動転記）」、🟦 5. 今日決まったこと、🟨 6. を読み込む。**すべて生成の材料としてのみ使う。書き換えない。**

### 3. アジェンダ1・4の「🤖 議論の記録」を埋める

ページの構造は次のとおり。**埋めるのは 🤖 の2箇所と ⏺️ だけ。**

```
🟩 共有しておきたいこと                    ← 読むだけ
0. 前回の決定と持ち帰りの確認
   ▸ 🟦 前回の持ち帰り（自動転記）          ← 3列だけ埋める（手順3-2）
   ▸ 🟩 経営・組織課題ボードの進捗確認       ← 触らない
1. 執行役員からの相談
   ▸ 🟩 事前記入                           ← 読むだけ
   ▸ 🤖 議論の記録                         ← ここを埋める
4. 取締役からの共有・依頼・相談
   ▸ 🟩 事前記入 ／ ▸ 🤖 議論の記録        ← 🤖 を埋める
⏺️ 文字起こし（自動要約）                  ← ここを埋める（手順3-3）
🟦 5. 今日決まったこと                     ← 触らない
🟨 6. 経営課題ボードの更新                 ← 触らない
```

各 🤖 の形式は雛形のまま変えない。

- **1. 執行役員からの相談** — 箇条書き。`- 相談者：` `- 論点：` `- 出た意見：` の3行を1件として、**🟩 事前記入に書かれた件ごとに繰り返す。** 事前記入の順に並べる。事前記入にあるが会議で扱われなかった件は、論点だけ書き「この場では扱わなかった」と残す。
- **4. 取締役からの共有・依頼・相談** — 表（件名／出た意見／担当・期限）。

**事前記入になく、当日その場で議論になった件の扱い。** 🟩 共有しておきたいこと に書かれた件が会議で議論された場合や、事前記入のないまま挙がった件は、アジェンダ1の末尾に1件として足し、`- 相談者：` の行に**事前記入がない旨と、誰が説明したか**を添える。議論を落とさないための例外であり、🟩 の欄そのものには書き込まない。

**対応する発言がなければ、その 🤖 は雛形のまま空欄で残す。** 他のアジェンダの内容を移してきて埋めてはいけない。

### 3-2. 0. の持ち帰り表に、進捗・共有・相談事項・ステータスを入れる

0. の「🟦 前回の持ち帰り（自動転記）」表の**各行**について、文字起こしから次の3列だけを埋める。担当・内容・期限は触らない。

| 列 | 値 |
|---|---|
| `今回の進捗` | `あり` / `なし`。その件に触れた発言があれば `あり` |
| `共有・相談事項` | `あり` の場合のみ。自由記載で簡潔に。`なし` なら空欄 |
| `ステータス` | `完了` / `継続` |

- **`完了` にするのは、完了したと明言された件だけ。** 曖昧なものは `継続`（迷ったら残す側へ倒す）。
- 進捗が `なし` の件は `継続`。
- 今回の進捗とステータスは**選択式の値だけを入れる**（自由記述にしない）。
- **すでに人が入れた値は上書きしない。** 空のセルだけを埋める。
- 担当・内容・期限と、出典リンク、`<mention-user>` は一字も変えない。
- 表の下の「未完了・遅れているもの：」「届いていなかった情報：」は人の欄なので触らない。
- 表に行が1つもなければ、何も書かずにそのまま残す。

### 3-3. ⏺️ 文字起こし（自動要約）を格納する

「Gemini によるメモ」の**要約部分（概要／決定事項／次のステップ／詳細）を、加工せずにそのまま**格納する。

- `（ここに自動要約を格納）` のプレースホルダを置き換える。見出しの `**自動要約**` とトグル自体は残す。
- **逐語の文字起こし本文は格納しない。** 個別社員の処遇などの生の発言が残るため。雛形の説明文にもそう書いてある。
- 要約し直さない。言い回しを整えない。Geminiの出力をそのまま運ぶ。
- 末尾に取得元を1行足す：`**取得元**：Google Meet「Gemini によるメモ」 [URL](URL)`
- **要約の中に個別社員の評価・処遇に関する記述が含まれていた場合は、その項目だけ落とす。** 落としたことは報告に挙げる（内容は書かない）。

### 4. ページに書き込む

`notion-update-page` の `update_content` を使う。`content_updates` に、埋める箇所ごとに1件ずつ渡す。

`old_str` は `notion-fetch` で取得した本文からそのまま切り出す。**`🤖 議論の記録` はページ内に2回出るので、`old_str` にはその直後の中身（`- 相談者：` の箇条書きか、`| 件名 | 出た意見 | 担当・期限 |` の列見出し）まで含めて一意にする。**

**🟩 と 🟦 のデータ行を `old_str` に含めない。** 見出し行と表の枠だけを触れば、中身に触らずに済む。事前記入にはコメントスレッド（`<span discussion-urls="...">`）やページメンション（`<mention url="...">`）が埋まっていることがあり、写し間違えると壊れる。

### 5. プロパティを更新する

`notion-update-page` の `update_properties` で以下を設定する。

| プロパティ | 値 |
|---|---|
| `ステータス` | `記録済` |
| `参加者` | 文字起こしで発言が確認できた人。`["久保","中井","盛島","山口","古本","多加谷","藤本","福有","宮本"]` から選ぶ |
| `欠席` | **欠席が明言された人だけ。** 発言がないだけの人は入れない |
| `決定事項` | 🟦 5. の表を1行に転記する。**要約はするが、書かれていない決定を足さない** |
| `関連する課題ボード#` | 🟦 5. と 🟩 の「課題ボード#」列に書かれた番号。空なら空のまま |
| `Zoom録画` | 「Gemini によるメモ」のURL |

**`次回への持ち越し` は空のままにする。** 読み取り元の欄が雛形にないため、AIが判断して埋めない。

**出欠の扱いに注意。** 発言がないことは欠席の証拠にならない。一度も発言せず、第三者として言及されているだけの参加者は、**参加者にも欠席にも入れず、報告で「出欠が確認できなかった」と挙げる。**

### 6. 書き込みを検証する

`notion-fetch` でページを再取得し、次を確認する。**ここが本処理でいちばん重要な確認。**

- 🟦 5. 今日決まったこと の表が、書き込み前と1文字も変わっていないこと
- 0. の「🟦 前回の持ち帰り（自動転記）」は、担当・内容・期限・出典リンクが変わっておらず、変わったのが 今回の進捗／共有・相談事項／ステータス の空だったセルだけであること
- 🟨 6. が変わっていないこと
- 🟩 共有しておきたいこと と、各アジェンダの 🟩 事前記入 が変わっていないこと。`discussion-urls` と `<mention url="...">` が消えていないこと
- 🤖 / ⏺️ 以外の見出し・凡例の表・区切り線が変わっていないこと

差分があれば、Slackへは投稿せず、何が変わってしまったかを報告する。

### 7. Slackへ投稿する

`slack_channel_id` が空の場合は投稿せず、本文を出力して終了する。`slack_mode` に従う（`send` なら `slack_send_message`、`draft` なら `slack_send_message_draft`）。

```
【経営レイヤー定例（人事版） MM/DD】議事録ができました → （Notionリンク）
・決まったこと：（🟦 5. から転記）
・課題ボードの更新が必要な件：#（オーナー名）
※ 誤りがあればNotionを直接修正してください（スレッドでの議論はお控えください）
```

- **見出しに「（人事版）」を必ず入れる。** 同じチャンネルへ事業版（月曜）も投稿するため、入れないとどちらの回か分からなくなる。
- 🟦 5. が空欄のまま会議が終わっていた場合は、「決まったこと」の行に「（Notionの 🟦 5. が未記入です）」と書く。**AIが議論から決定事項を作らない。**
- 🟨 6. が未記入なら「なし（🟨 6. が未記入のため）」と書く。
- 出欠が確認できなかった人がいた場合は、`※ ◯◯さんの出欠が文字起こしから確認できませんでした。Notionの参加者欄をご確認ください。` を足す。

Slackに貼るリンクは `https://www.notion.so/（ページIDをハイフンなし）` の形にする。

## 【厳守】

- **🟦 5. 今日決まったこと には一切書き込まない。0. の「前回の持ち帰り（自動転記）」は手順3-2の3列だけ書き込める。**
- **🟩 の事前記入欄・共有しておきたいこと欄も上書きしない。** 読み取り専用として扱う。要約もしない。
- **🟨 6. はオーナーの欄。触らない。**
- 発言の要約はするが、言っていないことを補わない。
- 発言者が特定できない発言は「発言者不明」と明記する。
- **個別社員の評価・処遇に関する発言は議事録に残さない。** この会議体は人事・組織が主題のため、文字起こしに特定個人の処遇・退職・評価の話が含まれる可能性が事業版より高い。1on1でのフィードバック内容、特定個人の退職の見込み、マネージャー適性の評価などは、🤖 にも ⏺️ にも書かない。**制度としての論点（等級・評価・報酬制度の設計、みなし残業の時間数、退職面談の仕組み化）は書いてよい。**
- アジェンダの枠に対応する発言がなければ空欄のままにする（推測で埋めない）。

## 報告

最後に、次の内容を標準出力へ報告する。

- 対象日と、対象になったNotionページのURL
- 文字起こしの取得元（カレンダー添付／Drive検索／取得できず）
- 埋めた 🤖 と、空欄のまま残した 🤖。⏺️ を格納したか
- 事前記入になく当日その場で議論になった件を足した場合は、その旨
- 持ち帰り表：進捗あり／なしの件数、`完了` にした件（内容）、`継続` の件数
- 更新したプロパティと、空のままにしたプロパティ
- 🟩 / 🟦 / 🟨 の検証結果
- 出欠が確認できなかった人
- 除外した発言・要約項目があればその旨（内容は書かない。「個別社員の処遇に関する記述を除外した」だけでよい）
- Slack投稿の有無（未投稿ならその理由）
