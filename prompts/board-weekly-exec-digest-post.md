# D-2　取締役週次定例：承認を確認して執行役員レイヤーへ投稿する

対象会議：`board-weekly`（取締役週次定例）
設定：`config/meetings.json` の `meetings.board-weekly.exec_digest`
実行タイミング：月曜 18:00（`post_time`）。承認の期限は 17:30（`approval_deadline`）で、D-1 の DM にもそう書いてある。

D-1 がオーナーへ DM で出した共有案について、**承認が返っているかを確認し、承認されている場合だけ**投稿してください。投稿は **2本**。チャンネルに**本体**を立て、続けてその**スレッドへ「当日の議論の内容」**を投稿します。

予約投稿（`slack_schedule_message`）は使わない。本体を予約すると、そのメッセージの `ts` が実行時に取れず、スレッドを紐づけられないため。この処理自体を 18:00 に走らせ、`slack_send_message` で投稿する。

**承認が確認できない場合は投稿しません。** これがこの処理の既定の結果です。

---

## 手順

### 1. 承認依頼の DM を探す

1. `approval_dm_user_id` との DM を `slack_read_channel` で読み、**対象日に D-1 が送った承認依頼メッセージ**を探す。冒頭が `取締役週次定例（MM/DD）の執行役員向け共有案です。` で始まるもの。
2. 見つからない場合は、D-1 が動いていないか失敗している。**投稿せず、その旨を報告して終了する。**
3. 同じ対象日の承認依頼が複数ある場合は、**いちばん新しいもの**を対象にする（修正を反映して出し直された案がある、ということ）。

### 2. 承認を判定する

`slack_read_thread` で、そのメッセージのスレッドと、DM上の後続メッセージを読む。

**投稿してよいのは、次のすべてを満たすときだけ。**

- 返信の投稿者が `approval_dm_user_id` 本人であること
- その返信が、`approval_words`（`承認` / `OK` / `オッケー` / `投稿して` / `これで`）のいずれかを含み、**承認の意思としてそのまま読めること**
- その返信より後に、同じ人からの修正指示・保留・取り消しがないこと

次のいずれかに当たる場合は、**承認とみなさない。**

- 返信がない
- 「ここを直して」「◯◯は落として」など、修正を求める内容が含まれる（`OK, ただし〜` のように承認語が混ざっていても、修正指示が入っていれば承認ではない）
- 承認とも修正ともつかない（「見ました」「あとで見ます」など）
- 承認語はあるが、どの案に対するものか判別できない

**判別できないときは投稿しない。** 承認の解釈を広げると、承認していない内容が執行役員へ届く。ここは狭く倒す。

### 3-A. 承認されている場合：本体とスレッドを投稿する

1. D-1 の DM から、**2本の本文をそのまま**取り出す。文言を直さない。整形もしない。承認されたのはこの文面であって、これに手を入れたものではない。

   | 取り出す範囲 | 投稿先 |
   |---|---|
   | `――――― 投稿案・本体（ここから） ―――――` 〜 `（ここまで）` | `post_channel_id` のチャンネル |
   | `――――― 投稿案・スレッド（ここから） ―――――` 〜 `（ここまで）` | 直前に投稿した本体のスレッド |

2. `slack_send_message` で `post_channel_id` へ本体を投稿する。返ってきたメッセージの `ts` を控える。
3. 同じ `slack_send_message` を `thread_ts` に手順2の `ts` を入れて呼び、スレッド本文を投稿する。`reply_broadcast` は付けない（チャンネルに二重に流れるため）。
4. **本体の投稿に成功してスレッドの投稿に失敗した場合は、本体を消さない。** スレッドが落ちたことを報告し、DM へその旨を返信する。サマリーだけが残ると伏せている印象になるので、人が手でスレッドを足せるよう、スレッド本文を報告にそのまま出す。
5. 投稿の結果（本体のメッセージリンク、スレッドの投稿有無）を、DM のスレッドへ返信して知らせる。
6. D-1 の報告に「🟦 に無い依頼を『執行役員のみなさんへ』に載せた」とある場合は、DM への返信に次の1行を添える。

   ```
   この依頼は 🟦「執行役員連携事項」に未記載です。次回の経営レイヤー定例のアジェンダ4に載せるには、議事録の 🟦 へ追記が必要です。
   ```

- 実行時刻が `post_time` を過ぎていても、**対象日の当日中**であればそのまま投稿してよい。日をまたいでいたら投稿せず報告して終了する。本文が「本日午前の取締役週次定例」と書かれているため、翌日以降に投稿すると本文が嘘になる。

### 3-B. 修正指示が返っている場合：直した案を出し直す

1. `prompts/board-weekly-exec-digest.md` の手順2〜5（読んでよい欄／非公開カテゴリ／粒度の落とし方／投稿案の形）に**そのまま従って**、指示を反映した案を作り直す。
2. **オーナーが名指しで「これは載せてよい」と指示した件は載せる。** 公開範囲を決めるのはオーナーであって、この処理ではない（`board-weekly-exec-digest.md` の手順4-2）。ただし**指示された件そのものだけ**を載せ、同じ議論に出てきた別の件まで広げない。指示が「どこまで」を含むのか読み取れない場合は、狭いほうで作り、確認を1行添える。
3. 🟦 に無い依頼を「執行役員のみなさんへ」へ足した場合は、案を出し直すときに、その件がアジェンダ4に自動では乗らないことを1行添える。
4. 作り直した案を、**同じ DM のスレッドへ返信**して出す。形式は D-1 の承認依頼と同じ（本体・スレッドの2本とも出す）。
5. **投稿はしない。** 出し直した案の承認は、次のリトライか手動実行で確認する。

### 3-C. 返信がない場合：投稿しない

1. 投稿せず、DM のスレッドへ「承認が確認できなかったため、本日の投稿は行いませんでした」と1行返信する。
2. 催促を重ねない。翌週の回で改めて案が出る。

---

## 【厳守】

- **承認が確認できないかぎり投稿しない。** これが既定の動作。
- 投稿する本文は、DM の投稿案ブロック（本体・スレッドの2つ）から**一字一句そのまま**取り出す。この処理で文面を作らない・直さない・付け足さない。
- **本体だけを投稿して終わらない。** スレッドの投稿まで含めて1つの投稿。スレッドに失敗した場合も本体は消さず、人が手で足せる形で報告する。
- `slack_schedule_message` は使わない。本体の `ts` が取れず、スレッドを紐づけられない。
- 承認語が含まれていても、後続に修正指示・保留があれば投稿しない。
- 承認の対象がどの案か判別できない場合は投稿しない。
- Notion には一切書き込まない。
- `post_channel_id` が空の場合は投稿せず、投稿するはずだった本文を出力して終了する。
- `@here` `@channel` を付けない。
- 同じ対象日について既に投稿済み・予約済みの場合は、二重投稿を避けて終了する。DM のスレッドに D-2 の完了報告が残っているかで判定する。

## 報告

- 対象日と、参照した承認依頼 DM の `thread_ts`
- 承認の判定結果（承認された／修正指示／返信なし／判別できず）と、そう判定した根拠になった返信の文面
- 投稿した場合：投稿先チャンネル、投稿時刻、本体のメッセージリンク、スレッドの投稿の成否
- 🟦 に無い依頼を載せていた場合：その件名と、🟦 への追記が必要な旨
- 投稿しなかった場合：その理由
