# A-3　経営レイヤー定例【人事版】：次回分の準備

対象会議：`hr-layer`（経営レイヤー定例【人事版】／火曜 14:00-15:00 JST）
実行タイミング：金曜 12:00（A-2 と同じ枠）

経営レイヤー定例【人事版】の次回分の準備をしてください。事業版（`exec-layer`）と運用は同じで、違いは次の3点だけ。

- Notion の DB・雛形・設計ページが別（`config/meetings.json` の `hr-layer`）。
- **処理C（取締役週次定例からの転記）は行わない。** 取締役週次定例の「執行役員連携事項」は事業版のアジェンダ4へ渡る。人事版のアジェンダ4は 🟩 事前記入を人が書く欄のまま。
- Slack は `hr-layer.slack_channel_id` が空の間は投稿せず、本文を出力して終了する。

---

## 手順

### 1. 次回開催を確認する

1. Google Calendar の `list_events` で、実行日から10日先までを対象に予定を取得し、タイトルが `calendar_title_keywords` の**いずれか1つ**を含む予定を探す。いちばん近い1件を次回開催とする。

   現行の予定名は「経営レイヤーmtg（人事系）」。`list_events` の `fullText` は曖昧検索で期待どおりに絞れないことがあるため、期間で全件取得してタイトルで自分で絞る。
2. 次回予定が見つからない場合は、**その旨だけ報告して終了する。**
3. 進行役を確認する。記載がなければ進行は設定せず、Slack投稿の（進行：◯◯）も省略する。輪番をAIが推測しない。

### 2. 次回分のページを作る

1. 次回開催日のページが既にあるか `notion-search` で確認する。

   ```
   notion-search: query="経営レイヤー定例（人事版） 議事録",
                  data_source_url="collection://27870844-8f1a-41d5-819b-3a340654fb3a"
   ```

   既にあれば**作成せず**手順3へ進む。
2. `notion-duplicate-page` で雛形ページ `4132fd3d-feaf-81a6-b66d-df0395c90048` を複製する。

   **複製したページは事業版のDB（雛形の置き場所）ではなく、人事版の議事録DBにあることを確認する。** 雛形が人事版DBの中にあるので通常はそうなる。違う場合は `notion-move-pages` で人事版DB（`data_source_id: 27870844-8f1a-41d5-819b-3a340654fb3a`）へ移す。
   複製は**1回につき1ページずつ**行う。続けて複数回呼ぶと、空の「新規ページ」が残ることがある。
3. `update_properties` で以下を設定する。

   | プロパティ | 値 |
   |---|---|
   | `タイトル` | `YYYY-MM-DD 経営レイヤー定例（人事版）`（次回開催日） |
   | `開催日` | 次回開催日（時刻は入れない） |
   | `ステータス` | `事前記入中` |
   | `進行` | 手順1で確認できた場合のみ |

   このDBのステータスは `事前記入中` / `記録済` / `確認済` の3つ。
4. `update_content` で、冒頭の引用ブロック「このページを複製して、毎回の議事録として使います。」を削除する。それ以外の本文は雛形のまま残す。

### 3. 前回の決定・持ち帰りを転記する

1. `notion-search` で、人事版DBから、次回開催日より前で最も新しい `YYYY-MM-DD 経営レイヤー定例（人事版）` のページを探す。`【雛形】` は除く。**事業版DBのページは見ない。**
2. 次の2つを拾う。
   - **前回ページの 0. 「🟦 前回の持ち帰り（自動転記）」表のうち、ステータスが `完了` でない行。** ステータスが空欄の行も残す。`完了` の行は持ち込まない。
   - **前回ページの 🟦 5. 今日決まったこと の表**から、初動の期限が次回開催日以前のもの、および期限が未設定のもの。
   同じ内容が両方にある場合は1行にまとめる。
3. 拾った内容を、新規ページの **0. 前回の決定と持ち帰りの確認 → 「🟦 前回の持ち帰り（自動転記）」の表** へ書き込む。列は 担当／内容／期限／今回の進捗／共有・相談事項／ステータス。**今回の進捗・共有・相談事項・ステータスは空欄にする。** 見出し行は雛形のまま変えない。前回から継続する行は、担当・内容・期限・出典をそのまま写す。

   この表は共通ルール §1-1 の「（自動転記）」欄。前回ページには触らない（読むだけ）。
4. 担当者が `<mention-user url="user://…"/>` で書かれている場合は、そのメンションのまま写す。
5. 拾うものが0件（初回を含む）なら、表を空のまま残す。

### 4. Slackへ投稿する

`slack_channel_id` が空の場合は投稿せず、本文を出力して終了する。

```
＠経営メンバー　次回の経営レイヤー定例（人事版）は MM/DD(曜) hh:mm〜 です（進行：◯◯）

■ 話したいことを、下記Notionページの各アジェンダの「事前記入」欄へ
　ご記入ください（当日午前中まで／1分で終わります）
　→ （Notionページのリンク）

■ 前回からの持ち越し
　・（担当）：（内容／期限）
```

## 【厳守】

- **該当のない行・ブロックは丸ごと省略する**（空行を並べない）。
- **資料の提出は求めない。** 記入は1行で足りると明記する。
- **記入先はNotionに一本化する。** Slackスレッドに書くよう促さない。
- 同じ日付のページが既にある場合は作成しない。
- 書き込むのは2箇所だけ。0. の「🟦 前回の持ち帰り」表と、プロパティ。**それ以外の 🟩 / 🟦 / 🤖 / 🟨 には触らない。** アジェンダ4の「🟩 事前記入」にも書き込まない（処理Cは人事版にはない）。
- 投稿は敬体で書く。命令調にしない。

## 報告

最後に、次の内容を標準出力へ報告する。

- 次回開催日時と、確認できた進行役（できなければその旨）
- 作成したNotionページのURL、または既存ページを使った旨
- 転記した前回の持ち帰りの件数と、転記元のページ
- Slack投稿の有無（未投稿ならその理由）。投稿しなかった場合は、投稿するはずだった本文
