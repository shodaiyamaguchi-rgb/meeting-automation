# A-3　経営レイヤー定例【人事版】：次回分の準備

対象会議：`exec-layer-hr`（経営レイヤー定例【人事版】）
実行タイミング：B-3（議事録生成）の直後に続けて実行する。火曜開催なので、会議後の議事録生成と同じ火曜夕方（B-3 のルーティンに連結）。B-3 が空振りした回のリトライ（水曜）でも、B-3 の直後に続けて実行する。

**対象日（`TARGET_DATE`）は「いま終わった回」の開催日。** 「次回」はその次の開催を指す。実行日ではなく `TARGET_DATE` を基準に読むこと。

経営レイヤー定例【人事版】の次回分の準備をしてください。

## 事業版（A-2）との違い

**この処理には、事業版の手順4にあたる「処理C（取締役週次定例からの転記）」がない。**

取締役週次定例の 🟦「執行役員連携事項」は、**事業版（`exec-layer`）のアジェンダ4へ一本化して転記する。** 人事版でも転記すると、同じ提案が2つの会議体へ二重に渡り、どちらで扱うのかが曖昧になる。**人事版のアジェンダ4「🟩 事前記入」には、この処理は一切書き込まない。**

そのほか、参照するDB・カレンダーの予定名・ページタイトルが事業版と異なる（`prompts/exec-layer-hr-minutes.md` の「事業版との違い」の表を参照）。

## 前提の確認（最初に行う）

この処理は、B-3 が埋めた「前回の持ち帰り」表の結果を次回ページへ写す。**B-3 が済んでいることが前提。**

1. `notion-search` で `TARGET_DATE` のページ（`YYYY-MM-DD 経営レイヤー定例（人事版）`）を探す。`data_source_url` に人事版のものを必ず指定する。
2. ページが見つからない、またはステータスが `事前記入中` のままなら、B-3 が書き込めていない。**何も書かずに、その旨だけ報告して終了する。** 持ち帰り表の進捗とステータスが空のまま次回へ写すと、完了した件が次回以降に残ってしまうため。翌日のリトライ（B-3 → A-3 の順）で拾う。
3. ステータスが `記録済` または `確認済` なら、以降の手順へ進む。

---

## 手順

### 1. 次回開催を確認する

1. Google Calendar の `list_events` で、`TARGET_DATE` の翌日 00:00 から10日先までを対象に予定を取得し、タイトルが `calendar_title_keywords` の**いずれか1つ**を含む予定を探す。`calendar_title_exclude` に一致するものは除く。いちばん近い1件を次回開催とする。`TARGET_DATE` 当日の回（いま終わった回）は次回に数えない。

   **人事版の予定名には「定例」が入らない**（例：`経営レイヤーmtg（人事系）`）。`list_events` の `fullText` は曖昧検索で期待どおりに絞れないことがあるため、期間で全件取得してタイトルで自分で絞るほうが確実。**月曜の事業版の回を拾わないよう、除外キーワードの確認を忘れない。**
2. 次回予定が見つからない場合は、**その旨だけ報告して終了する。**
3. 進行役を確認する。記載がなければ進行は設定せず、Slack投稿の（進行：◯◯）も省略する。輪番をAIが推測しない。

### 2. 次回分のページを作る

1. 次回開催日のページが既にあるか `notion-search` で確認する。既にあれば**作成せず**手順3へ進む。
2. `notion-duplicate-page` で人事版の雛形ページ（config の `template_page_id`）を複製する。**事業版の雛形と取り違えないこと。**
3. `update_properties` で以下を設定する。

   | プロパティ | 値 |
   |---|---|
   | `タイトル` | `YYYY-MM-DD 経営レイヤー定例（人事版）`（次回開催日） |
   | `開催日` | 次回開催日（時刻は入れない） |
   | `ステータス` | `事前記入中` |
   | `進行` | 手順1で確認できた場合のみ |

   このDBのステータスは `事前記入中` / `記録済` / `確認済` の3つ。「自動生成済」は存在しない。
4. `update_content` で、冒頭の引用ブロック「このページを複製して、毎回の議事録として使います。」を削除する。それ以外の本文は雛形のまま残す。

### 3. 前回の決定・持ち帰りを転記する

1. 転記元は、**`TARGET_DATE` のページ（いま B-3 が書き込み済みの回）。** 前提の確認で見つけたページをそのまま使う。
2. 次の2つを拾う。
   - **前回ページの 0. 「🟦 前回の持ち帰り（自動転記）」表のうち、ステータスが `完了` でない行。** ステータスが空欄の行も残す（B-3 が判定できなかったものは落とさない）。`完了` の行は**持ち込まない。**
   - **前回ページの 🟦 5. 今日決まったこと の表**から、初動の期限が次回開催日以前のもの、および期限が未設定のもの。
   同じ内容が両方にある場合は1行にまとめる。
3. 拾った内容を、新規ページの **0. 前回の決定と持ち帰りの確認 → 「🟦 前回の持ち帰り（自動転記）」の表** へ書き込む。列は 担当／内容／期限／今回の進捗／共有・相談事項／ステータス。**今回の進捗・共有・相談事項・ステータスは空欄にする**（会議後に B-3 が埋める）。見出し行は雛形のまま変えない。前回から継続する行は、担当・内容・期限をそのまま写し、出典も元のまま残す。

   出典がまだ付いていない行には `（出典：[MM/DD 経営レイヤー定例（人事版）](ページURL)）` を内容欄の末尾に足す。

   **この表はマークが 🟦 だが、見出しに「（自動転記）」が付いている＝この処理が書き込む欄。** 共通ルール §1-1 の例外にあたる。前回ページに人が書いた内容を写すだけで、内容をAIが作ることはしない。前回ページには触れない（読むだけ）。
4. 担当者が `<mention-user url="user://…"/>` で書かれている場合は、**そのメンションのまま写す。** 名前のテキストに置き換えない。
5. 拾うものが0件なら、表を空のまま残す。

### 4. 再実行の扱い

次回ページが既にあり、0. の表にも行が入っている場合は、手順3の転記をやり直さない（二重に書かない）。

### 5. Slackへ投稿する

`slack_channel_id` が空の場合は投稿せず、本文を出力して終了する。`slack_mode` に従う。

```
＠経営メンバー　次回の経営レイヤー定例（人事版）は MM/DD(曜) hh:mm〜 です（進行：◯◯）

■ 話したいことを、下記Notionページの各アジェンダの「事前記入」欄へ
　ご記入ください（当日午前中まで／1分で終わります。いつでも書き足せます）
　→ （Notionページのリンク）

■ 前回からの持ち越し
　・（担当）：（内容／期限）
```

**見出しに「（人事版）」を必ず入れる。** 同じチャンネルへ事業版（月曜）の案内も投稿するため、入れないとどちらの回か分からなくなる。

## 【厳守】

- **該当のない行・ブロックは丸ごと省略する**（空行を並べない）。
- **資料の提出は求めない。** 記入は1行で足りると明記する。
- **記入先はNotionに一本化する。** Slackスレッドに書くよう促さない。
- 同じ日付のページが既にある場合は作成しない。**そのうえで、今回の実行で新たに書き込んだ行が0件なら、Slackへは投稿しない**（リトライや再実行での二重投稿を避ける）。ただし、ページを新規作成した回は、転記が0件でも案内を投稿する（記入先を知らせる必要があるため）。
- 書き込むのは2箇所だけ。新規ページのプロパティと、0. の「🟦 前回の持ち帰り」表。**それ以外の 🟩 / 🟦 / 🤖 / ⏺️ / 🟨 には触らない。**
- **アジェンダ4の「🟩 事前記入」には書き込まない。** 取締役週次定例からの転記は事業版に一本化している。
- 投稿は敬体で書く。命令調にしない。

## 報告

最後に、次の内容を標準出力へ報告する。

- 次回開催日時と、確認できた進行役（できなければその旨）
- 作成したNotionページのURL、または既存ページを使った旨
- 転記した前回の持ち帰りの件数と、転記元のページ
- Slack投稿の有無（未投稿ならその理由）
