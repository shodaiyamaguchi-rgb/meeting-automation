# A-2 ＋ C　経営レイヤー定例：次回分の準備と取締役提案の転記

対象会議：`exec-layer`（経営レイヤー定例）
実行タイミング：開催2営業日前 09:00（月曜開催なので木曜）

経営レイヤー定例の次回分の準備をしてください。手順4が処理C（取締役週次定例からの転記）です。

---

## 手順

### 1. 次回開催を確認する

1. Google Calendar の `list_events` で、実行日から10日先までを対象に、タイトルに `calendar_title_keyword`（`経営レイヤー定例mtg`）を含む予定を探す。いちばん近い1件を次回開催とする。
2. 次回予定が見つからない場合は、**その旨だけ報告して終了する。**
3. 進行役を確認する。記載がなければ進行は設定せず、Slack投稿の（進行：◯◯）も省略する。輪番をAIが推測しない。

   この会議は 2026-08-24 の回で**隔週から週次に変更**が決まっている。カレンダーの繰り返し設定が隔週のままだと次回を取り違えるので、予定が2週間先しか見つからない場合はその旨を報告に含める。

### 2. 次回分のページを作る

1. 次回開催日のページが既にあるか `notion-search` で確認する。

   ```
   notion-search: query="経営レイヤー定例 議事録",
                  data_source_url="collection://232b1cc0-f19e-430d-a8b7-481a481560ce"
   ```

   既にあれば**作成せず**手順3へ進む。
2. `notion-duplicate-page` で雛形ページ `3c72fd3d-feaf-8132-886a-d605d12eebd3` を複製する。

   引き継ぎ書に載っている `3c52fd3d-feaf-81ff-bbe9-fcd8cf668363` は**ゴミ箱にあるので使わない。**
3. `update_properties` で以下を設定する。

   | プロパティ | 値 |
   |---|---|
   | `タイトル` | `YYYY-MM-DD 経営レイヤー定例`（次回開催日） |
   | `開催日` | 次回開催日（時刻は入れない） |
   | `ステータス` | `事前記入中` |
   | `進行` | 手順1で確認できた場合のみ |

   このDBのステータスは `事前記入中` / `記録済` / `確認済` の3つ。「自動生成済」は存在しない。
4. `update_content` で、冒頭の引用ブロック「このページを複製して、毎回の議事録として使います。」を削除する。それ以外の本文は雛形のまま残す。

### 3. 前回の決定・持ち帰りを転記する

1. `notion-search` で、次回開催日より前で最も新しい `YYYY-MM-DD 経営レイヤー定例` のページを探す。`【雛形】` は除く。
2. 前回ページの **🟦 5. 今日決まったこと** の表から、初動の期限が次回開催日以前のもの、および期限が未設定のものを拾う。
3. 拾った内容を、新規ページの **0. 前回の決定と持ち帰りの確認 → 「🟦 前回の持ち帰り」の表** へ書き込む。列は 担当／内容／期限／状態。状態は空欄にする。

   **この表はマークが 🟦 だが、A-2 が書き込む例外の欄。** 共通ルール §1-1 の3箇所のうちの1つ。前回ページに人が書いた内容を写すだけで、内容をAIが作ることはしない。前回ページの 🟦 5. には触らない（読むだけ）。
4. 担当者が `<mention-user url="user://…"/>` で書かれている場合は、**そのメンションのまま写す。** 名前のテキストに置き換えない。
5. 拾うものが0件なら、表を空のまま残す。

### 4. 【処理C】取締役週次定例からの提案を転記する

**設計意図：** 取締役週次定例で取締役が挙げた件のうち、会議中に「執行役員へ渡す」と仕分けられたものを、経営レイヤー定例で取締役提案として執行役員に共有する。取締役間の議論が取締役の中で閉じないようにするための導線。

1. `notion-search` で `取締役週次定例 議事録` を検索し、**前回の経営レイヤー定例の開催日より後、次回開催日より前**に開催された回のページをすべて拾う（週次開催なので通常1〜2回分）。
2. 各ページの **🟦 トグル「会議中の仕分け」→「執行役員連携事項」の表**を読む。列は 起案者／種別／内容。
3. 拾った各行を、新規ページの **アジェンダ4「取締役からの共有・依頼・相談」→「🟩 事前記入」の表**へ追記する。列が同じ（起案者／種別／内容）なので、**そのまま1対1で写す。内容を書き換えたり要約したりしない。**

   内容欄の末尾に、出典として取締役週次定例の議事録ページへのリンクを `（出典：MM/DD 取締役週次定例）` の形で足す。リンクは `[MM/DD 取締役週次定例](ページURL)` にする。

   **この表は 🟩 だが、処理C が書き込む例外の欄。** 共通ルール §1-1 の3箇所のうちの1つ。既に人が書いた行があれば、その下に追記する。既存行を消さない。
4. **🟦「取締役課題」の表は読まない。** そちらは取締役の中で持つと仕分けられた件で、執行役員へは渡らない。
5. **🟦 トグルがないページの扱い。** 🟦「会議中の仕分け」は 2026-08-25 に雛形へ追加した欄なので、それ以前に作られた回のページには存在しない。その場合は、

   - **Notionには何も書かない。**
   - 🤖 トグル内「5. 上程（候補）」の「経営レイヤー定例 議題4（取締役提案）の候補」に記載があれば、**候補として報告にだけ挙げる。**

   🤖 はAIが文字起こしから拾った候補であり、取締役が渡すと決めたものではない。決めていない提案が執行役員の見える場所に届くことを避けるため、人が判断するまで書かない。
6. 対象が0件の場合は**何も追記せず、Slack投稿でも触れない。**

### 5. Slackへ投稿する

`slack_channel_id` が空の場合は投稿せず、本文を出力して終了する。

```
＠経営メンバー　次回の経営レイヤー定例は MM/DD(曜) hh:mm〜 です（進行：◯◯）

■ 話したいことを、下記Notionページの各アジェンダの「事前記入」欄へ
　ご記入ください（当日午前中まで／1分で終わります）
　→ （Notionページのリンク）

■ 取締役週次定例から上がっている提案（アジェンダ4に記載済み）
　・（起案者）：（件名）

■ 前回からの持ち越し
　・（担当）：（内容／期限）
```

---

## 【厳守】

- **該当のない行・ブロックは丸ごと省略する**（空行を並べない）。手順4が0件なら「■ 取締役週次定例から上がっている提案」のブロックごと省略する。
- **資料の提出は求めない。** 記入は1行で足りると明記する。
- **記入先はNotionに一本化する。** Slackスレッドに書くよう促さない。
- 同じ日付のページが既にある場合は作成しない。
- 書き込むのは3箇所だけ。0. の「🟦 前回の持ち帰り」表、アジェンダ4の「🟩 事前記入」表、そしてプロパティ。**それ以外の 🟩 / 🟦 / 🤖 / 🟨 には触らない。**
- 処理Cで写す内容をAIが作らない。取締役が 🟦 に書いた文面をそのまま運ぶ。
- 投稿は敬体で書く。命令調にしない。

## 報告

最後に、次の内容を標準出力へ報告する。

- 次回開催日時と、確認できた進行役（できなければその旨）
- 作成したNotionページのURL、または既存ページを使った旨
- 転記した前回の持ち帰りの件数と、転記元のページ
- 処理C：読んだ取締役週次定例の回、転記した件数、転記した各件の起案者と件名
- 処理C：🟦 がないため転記せず候補として挙げた件（あれば）
- Slack投稿の有無（未投稿ならその理由）
