# 共通ルール（全処理に適用）

このルールは、個別プロンプトの手順より優先する。個別プロンプトの【厳守】と矛盾した場合のみ、個別プロンプト側を優先する。

## 1. 4マーク凡例（最重要）

議事録ページの各欄には、誰がいつ埋めるかを表すマークが付いている。

| マーク | いつ | 誰が | 自動化の扱い |
|---|---|---|---|
| 🟩 | 会議前 | 各自 | **読み取り専用**。上書き・要約・整形・削除を一切しない |
| 🟦 | 会議中 | 進行役 | **一切書き込まない**。空欄でも補完しない |
| 🤖 | 会議後 | 自動 | ここだけを書き込む |
| ⏺️ | 会議後 | 自動 | 文字起こしの原文と自動要約を、加工せずに格納する |
| 🟨 | 会議後 | オーナー（山口） | 自動化の対象外。触らない |

**🟦 に書き込まないことが、この自動化における最大の制約。** 決定内容・実行担当・期限は認識がずれやすく、AIが推測で埋めると誤った決定が一次情報として残る。空欄のまま会議が終わっていたとしても、埋めない。

### 1-1. 自動転記だけは例外（3箇所のみ）

雛形の作りと処理の都合で、🟩 / 🟦 のマークが付いていても自動化が書き込む欄が3つある。**この3つ以外には、マークが 🟩 / 🟦 の欄には一切書き込まない。**

| 欄 | マーク | 書き込む処理 | 中身 |
|---|---|---|---|
| 取締役週次定例：🟩 内の「前回の持ち帰り（自動転記）」表 | 🟩 | A-1 | 前回の持ち帰りの転記 |
| 経営レイヤー定例：0. の「🟦 前回の持ち帰り（自動転記）」表 | 🟦 | A-2 | 前回の決定・持ち帰りの転記 |
| 経営レイヤー定例：アジェンダ4 の「🟩 事前記入」表 | 🟩 | A-2（処理C） | 取締役週次定例からの提案の転記 |

いずれも**会議前**に、**別のページに人が書いた内容を写すだけ**の処理であり、文字起こしからの生成ではない。写す元がなければ何も書かない。この3つの欄でも、AIが内容を作ることはしない。

この3つはいずれも見出しに「（自動転記）」が付いている。**マークではなく、この語で判断すること。** 見出しに「（自動転記）」がない 🟩 / 🟦 の欄には、例外なく書き込まない。

## 2. 生成物の原則

- 発言の要約はする。言っていないことは補わない。
- アジェンダの枠に対応する発言がなければ、空欄のままにする。「特になし」とも書かない（人が書いた「なし」と区別がつかなくなるため）。
- 発言者が特定できない発言は「発言者不明」として扱う。推測で名前を当てない。
- 個別社員の評価・処遇に関する発言は議事録に残さない。
- **読み手が変わる出力では、出どころで切ってから内容で切る。** 取締役の議事録を執行役員へ渡すような処理では、まず「渡してよいと人が仕分けた欄」だけを材料にし、そのうえで内容を精査する。内容の判断だけに頼らない。迷ったものは載せない側へ倒し、判断は承認者へ渡す。
- 議論の途中経過より、決まったこと・持ち帰りを優先して記録する。

## 3. 失敗したときの振る舞い

- 前提（文字起こし、対象ページ、カレンダー予定）が欠けている場合は、**部分的に書き込まず、何も書かずに報告だけして終了する。**
- 二重実行の防止はステータスで判定する。判定できない場合は書き込まない。
- Notionへの書き込みが途中で失敗した場合、Slackへは投稿しない。人が状態を確認できるよう、どこまで進んだかを報告する。

## 4. Slack

- `slack_channel_id` が設定されていない会議体では、**Slackへ投稿しない。** 投稿するはずだった本文をそのまま出力して終了する。
- **`slack_mode` の値で投稿方法を変える。**

  | 値 | 使うツール | 挙動 |
  |---|---|---|
  | `draft` | `slack_send_message_draft` | 下書きとして置く。人が確認して送る |
  | `send` | `slack_send_message` | そのまま投稿する |

  既定は `send`（本投稿）。下書きで様子を見たいときだけ `config/meetings.json` の `slack_mode` を `draft` に変える。**`draft` のときに `slack_send_message` を使わない。**
- **執行役員レイヤーへの共有（D-1 / D-2）だけは `slack_mode` に従わない。** `slack_mode` が `send` でも、承認を経ずにチャンネルへ投稿しない。D-1 はオーナーへのDMだけを行い、D-2 が承認を確認してから投稿する。
- 投稿は敬体で書く。命令調にしない。
- 該当のない行・ブロックは丸ごと省略する。空行や「（なし）」を並べない。
- スレッドでの議論を促さない。修正はNotionを直接直してもらう。

## 5. Notionの書き込み方（実務）

- 書き込み前に必ず `notion-fetch` で対象ページの現在の本文を取得し、**取得した本文と完全一致する文字列**を `old_str` に使う。
- `notion-update-page` の `update_content` を使い、置換範囲は必要最小限にする。`replace_content`（ページ全体の置換）は使わない。🟩 や 🟦 を巻き込んで消す事故が起きるため。
- トグル（`<details>`）の中身はタブでインデントされている。`old_str` / `new_str` の**両方でタブのインデントを保つ**こと。インデントが崩れるとトグルの外に飛び出す。
- 表は Notion-flavored Markdown の `<table>` / `<tr>` / `<td>` で書く。セルの中に見出し・箇条書き・HTMLタグは入らない（リッチテキストのみ）。
- 書き込み後、`notion-fetch` で再取得し、🟩 と 🟦 の中身が書き込み前と一致していることを確認する。差分があれば元に戻し、報告する。
- Slackに貼るページリンクは `https://www.notion.so/（ページIDをハイフンなしで）` の形にする。`notion-fetch` や `notion-query-data-sources` が返す `https://app.notion.com/p/...` 形式のURLをそのままSlackに貼らない（開けないことがある）。
