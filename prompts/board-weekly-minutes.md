# B-1　取締役週次定例：会議後の議事録生成とSlack投稿

対象会議：`board-weekly`（取締役週次定例）
実行タイミング：会議終了の1時間後／翌朝08:00のリトライ

取締役週次定例の議事録を作成し、Slackへ展開してください。**対象日**（実行時コンテキストの `TARGET_DATE`）に開催された回が対象です。

---

## 手順

### 1. 文字起こしを取得する

1. Google Calendar の `list_events` で、対象日（00:00〜23:59 JST）の予定を取得する。タイトルに `calendar_title_keyword`（取締役週次定例）を含む予定を探す。
2. 予定が見つからない場合は、**その旨だけ報告して終了する。** Notionには何も書かない。
3. 予定の添付ファイル（attachments）から、Meetの文字起こしドキュメントを探す。Meetは録画と文字起こしの2つを添付するので、`Gemini`・`文字起こし`・`Transcript` を含む名前のドキュメント（Google Docs）を選ぶ。録画（動画ファイル）ではない。
4. 添付が見つからない場合は、Google Drive の `search_files` でフォールバックする。

   ```
   title contains '取締役週次定例' and modifiedTime > '{{対象日}}T00:00:00+09:00'
   ```

   それでも見つからない場合は、`title contains 'Meet Recordings'` の親フォルダ側から辿る。
5. `read_file_content` で本文を取得する。**文字起こしがまだ生成されていない場合は、その旨だけ報告して終了する。** 翌朝のリトライで再実行される。
6. 文字起こしドキュメントの共有URLを控える（あとでプロパティに入れる）。Meetの自動要約ドキュメントが別にある場合は、それも取得する。

### 2. Notionの対象ページを取得する

1. `notion-query-data-sources` で、議事録DBのデータソースから対象日のページを探す。

   ```sql
   SELECT url, "タイトル", "ステータス", "date:開催日:start"
   FROM "collection://f3605c0a-be8a-410e-86bb-66fc5253394a"
   WHERE date("date:開催日:start") = date(?)
   ```

   - タイトルが `【雛形】` で始まるページは対象外。雛形には絶対に書き込まない。
2. ページが見つからない場合は、**新規作成せず、その旨を報告して終了する。** ページの作成は A-1 の責務。
3. ステータスが「自動生成済」「確認済」「要修正」のいずれかなら、**二重実行を避けて終了する。** 対象は「事前記入中」のページのみ。
4. `notion-fetch` でページ本文を取得する。以降の置換に使うので、取得した本文はそのまま保持しておく。
5. 🟩 トグルの中身（【経営課題の提起】この場で話したいこと／【共有のみ】読んでおいてほしいこと／前回の持ち帰り）を読み込む。これは**生成の材料としてのみ使う。書き換えない。**
6. 🟦 トグル「執行役員へ渡すもの（会議中／進行役が記入）」の表を読み込む。会議中に進行役が書いた、次回の経営レイヤー定例へ渡す件の一覧。**読み取り専用。空でも埋めない。** Slack投稿の「次回の経営レイヤー定例へ提起」はこの表から作る。

### 3. 🤖 トグルの中身を生成する

ページの 🤖 トグル（`<summary>🤖 文字起こしのまとめ（会議後／自動生成）</summary>`）の中にある 0〜6 の各見出しの下を埋める。見出しの構成・順序・文言は雛形のまま変えない。

- **0. サマリー（3行）** — 3行。この回で何が動いたかがわかる粒度で書く。
- **1. 各自の共有と牽制** — 中井（CEO）／久保（社長）／盛島（CFO）／山口 の4名それぞれについて、「管掌の状況」「今週の主戦場」「薄くなっている場所」「見ておいてほしいこと」の4項目。欠席者や、その項目に対応する発言がない場合は空欄のままにする。
- **2. 相談・よもやま** — 「論点」「出た意見」「結論を出さなかったもの」「【共有のみ】への異論」。異論が出なければ「なし」と書く（この欄だけは明示的に「なし」と書いてよい。異論の有無自体が情報のため）。
- **3. 経営課題の優先度** — 「各自の1位」（4名分）、「揃わなかった差分と、その理由」、「今週の全社トップ3」（①②③）。
- **4. 持ち帰り** — 表（担当／内容／期限）。期限が発言されていない場合は空欄にし、推測で日付を入れない。
- **5. 上程（候補）** — 「経営レイヤー定例 議題4（取締役提案）の候補」「取締役会」。文字起こしから拾った候補であって、確定ではない。次回の経営レイヤー定例へ実際に渡るのは 🟦 に書かれたものだけで、この欄は進行役が 🟦 への書き漏らしに気づくための控え。**🟦 に書かれていない件をここに挙げてよい**（挙げるのが役目）。逆に、ここに挙げたものを 🟦 へ書き足してはいけない。
- **6. 未収録・要確認** — 判別できなかった箇所、発言者不明の発言、音声が途切れた区間。

### 4. ⏺️ トグルの中身を格納する

⏺️ トグル（`<summary>⏺️ 文字起こしの原文・自動要約（会議後／自動生成）</summary>`）に、文字起こしの原文とMeetの自動要約を**加工せずに**格納する。要約も整形も削除もしない。🤖 の記載に疑問が出たときの参照元なので、加工した時点で役目を失う。

- 原文が 30,000 文字を超える場合のみ、原文の格納をやめ、文字起こしドキュメントへのリンクと自動要約だけを格納する。その旨を1行書き添える。
- 冒頭に `取得元：（文字起こしドキュメントのリンク）` を置く。

### 5. ページに書き込む

`notion-update-page` の `update_content` を1回呼び、`content_updates` に**2件**の置換を渡す。

- 1件目：🤖 トグルの `<details>` 開始タグから対応する `</details>` までを丸ごと置換する。
- 2件目：⏺️ トグルの `<details>` 開始タグから対応する `</details>` までを丸ごと置換する。

`old_str` は手順2-4で取得した本文からそのまま切り出す。`new_str` は `<summary>` 行を変えず、中身のインデント（タブ）を保つ。この方法をとる理由は、置換範囲が 🤖 と ⏺️ のトグル内に閉じることが `old_str` の形から目視で確認でき、🟩 と 🟦 を巻き込む余地がないため。

`</details>\n<details>` はページ内に複数あるので、`old_str` には必ず対応する `<summary>` 行まで含めて一意にする。見出しごとの細かい置換に切り替えてもよいが、その場合も `old_str` にはタブ始まりの見出し行を含め、🟩 側の同名見出しと取り違えないこと。

### 6. プロパティを更新する

`notion-update-page` の `update_properties` で以下を設定する。

| プロパティ | 値 |
|---|---|
| `ステータス` | `自動生成済` |
| `参加者` | 実際に発言・参加していた人。`["中井","久保","盛島","山口"]` から選ぶ |
| `欠席` | 参加者に含まれない人。全員参加なら空 |
| `今週のトップ3` | 3. の全社トップ3を1行で |
| `上程先` | `["隔週会議 議題1","隔週会議 議題6","取締役会","なし"]` から。5. の内容に対応させる。上程がなければ `["なし"]` |
| `持ち越し` | 4. の持ち帰りを1行で。次週の議題0で読み上げる粒度 |
| `Zoom録画` | Meetの文字起こしドキュメントのURL |

`Zoom録画` は Zoom運用時代のプロパティ名がそのまま残っているもの。現在はMeetの文字起こしURLを入れる欄として使う。Notion側で名称が変わったら、このプロンプトも直すこと。

### 7. 書き込みを検証する

`notion-fetch` でページを再取得し、次を確認する。**ここが本処理でいちばん重要な確認。**

- 🟩 トグルの中身が、書き込み前と1文字も変わっていないこと
- 🟦 トグル「執行役員へ渡すもの」の表が、書き込み前と1文字も変わっていないこと。空欄のままでも空欄のまま
- 🤖 と ⏺️ のトグルの外側（ページ冒頭の表、見出し）が変わっていないこと
- 🤖 の見出し 0〜6 が欠けていないこと

差分があれば、Slackへは投稿せず、何が変わってしまったかを報告する。

### 8. Slackへ投稿する

`slack_channel_id` が空の場合は投稿せず、本文を出力して終了する。

```
【取締役週次定例 MM/DD】議事録ができました → （Notionリンク）
・今週の全社トップ3：①　②　③
・各自の主戦場：中井（　）久保（　）盛島（　）山口（　）
・持ち帰り：中井（内容／期限）久保（　）盛島（　）山口（　）
・次回の経営レイヤー定例へ提起：（件名／なければ「なし」）
※ 誤りがあればNotionを直接修正してください（スレッドで議論しない）
```

- 欠席者は「各自の主戦場」から行ごと省略する。
- 持ち帰りがない人は省略する。全員なければ行ごと省略する。
- 「次回の経営レイヤー定例へ提起」は **🟦 の表から**作る。件名を並べ、🟦 が空なら「なし」と書く。🤖 5. の候補で補わない。進行役が書かなかったものは渡らないという運用のため、ここで補うと運用が壊れる。

---

## 【厳守】

- 事前記入の【共有のみ】欄は、会議で触れられなくても消さず、要約もせず、記入された文面をそのまま残す。
- 【共有のみ】に対して会議中に異論が出た場合は 2. に記録する。出なければ「なし」。
- 【経営課題の提起】として記入されたのに会議で扱われなかった項目は、4. 持ち帰りに「次回へ持ち越し」として残す。この欄は次回の経営レイヤー定例で取締役提案として執行役員へ共有される導線に乗るため、落とすと導線ごと切れる。
- 発言の要約はするが、言っていないことを補わない。
- 発言者が特定できない発言は「発言者不明」として 6. に入れる。
- 個別社員の評価・処遇に関する発言は議事録に残さない。
- 議論の途中経過より、決まったこと・持ち帰りを優先して記録する。
- 🟩 トグルと 🟦 トグルには書き込まない。読むだけ。
- 🟦「執行役員へ渡すもの」が空のまま会議が終わっていても、埋めない。会議中に進行役が渡すと決めなかった、という記録として意味がある。

## 報告

最後に、次の内容を標準出力へ報告する（cronのログに残る）。

- 対象日と、対象になったNotionページのURL
- 文字起こしの取得元（カレンダー添付／Drive検索／取得できず）
- 書き込んだ欄と、更新したプロパティ
- 🟩 と 🟦 の検証結果
- 🟦 が空だったかどうか（空なら、進行役が会議中に記入していない可能性がある）
- Slack投稿の有無（未投稿ならその理由）
