# B-3　経営レイヤー定例【人事版】：議事録生成 ＋ 次回のたたき作成

対象会議：`hr-layer`（経営レイヤー定例【人事版】、火曜 14:00-15:00 JST）
実行タイミング：火曜 16:00 JST／翌日のリトライ

人事版の議事録を作成し、**同じ実行で次回分のたたき（ページ作成と前回の持ち帰りの転記）まで行う。** 対象日（`TARGET_DATE`）に開催された回が対象です。

構成は事業版の B-2（`exec-layer-minutes.md`）と A-2（`exec-layer-prep.md`）に揃えている。違いは次のとおり。

- アジェンダは 0・1・4 の3つ。事業版の 2・3 はない
- 取締役週次定例からの転記（処理C）はない
- 議事録DBは人事版のもの（`config/meetings.json` の `meetings.hr-layer`）。**事業版のDB・ページには書き込まない**

**前半（パートA：議事録）が成功して `記録済` になったときだけ、後半（パートB：次回のたたき）に進む。** 前半が終了条件に当たった場合は、後半に進まない（例外は下記）。

---

# パートA：議事録生成

## 手順

### 1. 文字起こしを取得する

1. Google Calendar の `list_events` で、対象日（00:00〜23:59 JST）の予定を取得する。タイトルが `calendar_title_keywords` の**いずれか1つ**を含む予定を探す。事業版（`経営レイヤー定例`）と名前が似ているので、**タイトルに「人事版」を含む予定だけを対象にする。** 事業版の予定を取り違えない。
2. 予定が見つからない場合は、その旨だけ報告して終了する。Notionには何も書かない。
3. 予定の `attachments` から「Gemini によるメモ」（Google Docs）を探す。要約と逐語の文字起こしが同居している。録画（Recording）は使わない。
4. 添付がなければ Google Drive の `search_files` でフォールバックする。

   ```
   title contains '経営レイヤー定例' and modifiedTime > '{{対象日}}T00:00:00+09:00'
   ```

   タイトルに「人事版」を含むものを選ぶ。
5. `read_file_content` で本文を取得する。**文字起こしがまだ生成されていない場合は、その旨だけ報告して終了する。** 翌日のリトライで再実行される。
6. ドキュメントのURLを控える。

### 2. Notionの対象ページを取得する

1. `notion-search` で探す。

   ```
   notion-search: query="経営レイヤー定例（人事版）",
                  data_source_url="collection://27870844-8f1a-41d5-819b-3a340654fb3a"
   ```

   タイトルが `YYYY-MM-DD 経営レイヤー定例（人事版）` の形で対象日と一致するページを選ぶ。`【雛形】` は対象外。**雛形には絶対に書き込まない。**
2. ページが見つからない場合は、新規作成せず、その旨を報告して終了する。
3. ステータスが `記録済` または `確認済` なら、**パートAは二重実行を避けて終了する。** このとき**パートBは実行する**（前日に議事録だけ成功し、たたきが未作成のまま終わっていた場合を拾うため。次回ページが既にあれば作らない）。対象は `事前記入中` のページのみ。

   ステータスは `事前記入中` / `記録済` / `確認済` の3つ。「自動生成済」は存在しない。
4. `notion-fetch` でページ本文を取得し、以降の置換に使うため保持する。
5. 🟩 共有しておきたいこと、各アジェンダの 🟩 事前記入、0. の「🟦 前回の持ち帰り（自動転記）」、「🟩 経営・組織課題ボードの進捗確認（自動転記）」、🟦 5. 今日決まったこと、🟨 6. を読み込む。**すべて生成の材料としてのみ使う。書き換えない。**

### 3. アジェンダ1・4の「🤖 議論の記録」だけを埋める

```
🟩 共有しておきたいこと                    ← 読むだけ
0. 前回の決定と持ち帰りの確認
   ▸ 🟦 前回の持ち帰り（自動転記）          ← 今回の進捗／共有・相談事項／ステータスの3列だけ埋める（手順3-2）
   ▸ 🟩 経営・組織課題ボードの進捗確認（自動転記） ← 触らない
1. 執行役員からの相談
   ▸ 🟩 事前記入                           ← 読むだけ
   ▸ 🤖 議論の記録                         ← ここを埋める
4. 取締役からの共有・依頼・相談
   ▸ 🟩 事前記入                           ← 読むだけ
   ▸ 🤖 議論の記録                         ← ここを埋める
⏺️ 文字起こし（自動要約）                   ← 自動要約を格納（手順3-3）
🟦 5. 今日決まったこと                     ← 触らない
🟨 6. 経営課題ボードの更新                 ← 触らない
```

- **1. 執行役員からの相談** — 箇条書き。`- 相談者：` `- 論点：` `- 出た意見：` の3行を1件として、🟩 事前記入に書かれた件ごとに繰り返す。事前記入の順に並べる。扱われなかった件は、論点だけ書き「この場では扱わなかった」と残す。
- **4. 取締役からの共有・依頼・相談** — 表（件名／出た意見／担当・期限）。

対応する発言がなければ、その 🤖 は雛形のまま空欄で残す。議論が別のアジェンダの時間に出た場合は、事前記入がある側に書く。

### 3-2. 0. の持ち帰り表に、進捗・共有・相談事項・ステータスを入れる

0. の「🟦 前回の持ち帰り（自動転記）」表の各行について、次の3列だけを埋める。担当・内容・期限は触らない。

| 列 | 値 |
|---|---|
| `今回の進捗` | `あり` / `なし`。触れた発言があれば `あり`、なければ `なし` |
| `共有・相談事項` | `あり` の場合のみ。自由記載で簡潔に。`なし` なら空欄 |
| `ステータス` | `完了` / `継続` |

- **`完了` にするのは、完了したと明言された件だけ。** 曖昧なものは `継続`。迷ったら残す側へ倒す。
- 進捗が `なし` の件は `継続`。
- 選択式の値だけを入れる。自由記述にしない。
- すでに人が入れた値は上書きしない。空のセルだけを埋める。
- 担当・内容・期限、出典リンク、`<mention-user>` は一字も変えない。
- 表の下の「未完了・遅れているもの：」「届いていなかった情報：」は人の欄なので触らない。

### 3-3. ⏺️ に自動要約を格納する

⏺️ トグルの「（ここに自動要約を格納）」を、Meetの自動要約に置き換える。**加工・要約し直しはしない。逐語の文字起こしは格納しない。** 個別社員の評価・処遇に関する部分は、共通ルール §2 に従い除く。

### 4. ページに書き込む

`notion-update-page` の `update_content` を使い、埋める箇所ごとに1件ずつ渡す。サブ欄はトグル見出しで、中身はタブでインデントされている。`old_str` / `new_str` の両方でタブを保つ。

**🟩 と 🟦 のデータ行を `old_str` に含めない。** 見出し行と `<table>` / `</table>` の行だけを触る。事前記入にはコメントスレッド（`discussion-urls`）やリンクが埋まっていることがあり、写し間違えると壊れる。`</table>\n### 🤖 議論の記録` は複数回出るので、列見出しまで含めて一意にする。

### 5. プロパティを更新する

| プロパティ | 値 |
|---|---|
| `ステータス` | `記録済` |
| `参加者` | 発言が確認できた人。`["久保","中井","盛島","山口","古本","多加谷","藤本","福有","宮本"]` から選ぶ |
| `欠席` | **欠席が明言された人だけ。** 発言がないだけの人は入れない |
| `決定事項` | 🟦 5. の表を1行に転記する。要約はするが、書かれていない決定を足さない |
| `関連する課題ボード#` | 🟦 5. と 🟩 の「課題ボード#」列に書かれた番号。空なら空のまま |
| `Zoom録画` | 「Gemini によるメモ」のURL |

`次回への持ち越し` は空のままにする（読み取り元の欄がなく、AIが判断して埋めることになるため）。発言がないだけの人は、参加者にも欠席にも入れず、報告で「出欠が確認できなかった」と挙げる。

### 6. 書き込みを検証する

`notion-fetch` で再取得し、次を確認する。**ここが本処理でいちばん重要な確認。**

- 🟦 5. 今日決まったこと が書き込み前と1文字も変わっていないこと（メンションが消えていないこと）
- 0. の「🟦 前回の持ち帰り（自動転記）」は、変わったのが 今回の進捗／共有・相談事項／ステータス の空だったセルだけであること
- 「🟩 経営・組織課題ボードの進捗確認（自動転記）」が変わっていないこと
- 🟨 6. が変わっていないこと
- 🟩 事前記入、🟩 共有しておきたいことが変わっていないこと（`discussion-urls` が残っていること）
- 🤖 と ⏺️ 以外の見出し・凡例・区切り線が変わっていないこと

**差分があれば、Slackへは投稿せず、パートBにも進まず、何が変わったかを報告して終了する。**

### 7. Slackへ投稿する（議事録）

`slack_channel_id` が空の間は投稿せず、本文を出力する。

```
【経営レイヤー定例【人事版】 MM/DD】議事録ができました → （Notionリンク）
・決まったこと：（🟦 5. から転記）
・課題ボードの更新が必要な件：#（オーナー名）
※ 誤りがあればNotionを直接修正してください（スレッドで議論しない）
```

- 🟦 5. が空欄なら「決まったこと」に「（Notionの 🟦 5. が未記入です）」と書く。AIが議論から決定事項を作らない。
- 🟨 6. が未記入なら「なし（🟨 6. が未記入のため）」と書く。
- 出欠が確認できなかった人がいれば `※ ◯◯の出欠が文字起こしから確認できませんでした。Notionの参加者欄をご確認ください。` を足す。

**Notionへの書き込みが途中で失敗した場合は、Slackへ投稿せず、パートBにも進まない。**

# パートB：次回のたたき作成

パートAで `記録済` になった直後（またはパートAが二重実行で終了した場合）に、続けて実行する。**議事録の確定後に実行する理由：** 0. の持ち帰り表の転記元は、今回のページの「今回の進捗・ステータス」であり、これが埋まってからでないと `完了` の行を除けない。

### B-1. 次回開催を確認する

1. `list_events` で、`TARGET_DATE` の翌日から10日先までを対象に、タイトルに「人事版」を含み `calendar_title_keywords` のいずれかに一致する予定を探す。いちばん近い1件が次回開催。
2. 見つからなければ、その旨だけ報告してパートBを終了する（パートAの結果は有効）。
3. 進行役はカレンダーに記載があれば設定し、なければ設定しない。輪番を推測しない。

### B-2. 次回分のページを作る

1. `notion-search` で次回開催日のページが既にあるか確認する。あれば**作成せず** B-3 へ進む（ページが既にあるときは、0. の表が埋まっていなければ B-3 だけ行う）。
2. `notion-duplicate-page` で雛形ページ `4132fd3d-feaf-81a6-b66d-df0395c90048` を複製する。
3. `update_properties`：

   | プロパティ | 値 |
   |---|---|
   | `タイトル` | `YYYY-MM-DD 経営レイヤー定例（人事版）` |
   | `開催日` | 次回開催日（時刻なし） |
   | `ステータス` | `事前記入中` |
   | `進行` | 確認できた場合のみ |

4. `update_content` で、冒頭の引用ブロック「このページを複製して、毎回の議事録として使います。」を削除する。それ以外は雛形のまま残す。

### B-3. 前回の持ち帰りを転記する

1. 転記元は、**パートAで記録した今回のページ**（`TARGET_DATE` のページ）。読むだけで、触らない。
2. 次の2つを拾う。
   - 0. 「🟦 前回の持ち帰り（自動転記）」表のうち、ステータスが `完了` でない行（空欄も残す）
   - 🟦 5. 今日決まったこと の表から、初動の期限が次回開催日以前のもの、および期限が未設定のもの

   同じ内容は1行にまとめる。
3. 新規ページの 0. 「🟦 前回の持ち帰り（自動転記）」表へ書き込む。列は 担当／内容／期限／今回の進捗／共有・相談事項／ステータス。**今回の進捗・共有・相談事項・ステータスは空欄にする。** 見出し行は雛形のまま。
4. `<mention-user>` はそのまま写す。名前のテキストに置き換えない。
5. 0件なら表を空のまま残す。
6. 新規ページの「🟩 経営・組織課題ボードの進捗確認（自動転記）」は、転記元と手順が定義されていないため**触らない**。報告で「未転記」と挙げる。

### B-4. 書き込みを検証する

新規ページを `notion-fetch` で再取得し、書き込んだのが プロパティ、冒頭の引用ブロックの削除、0. の持ち帰り表だけであることを確認する。今回のページ（転記元）が変わっていないことも確認する。

### B-5. Slackへ投稿する（次回の案内）

`slack_channel_id` が空の間は投稿せず、本文を出力する。

```
＠経営メンバー　次回の経営レイヤー定例【人事版】は MM/DD(曜) hh:mm〜 です（進行：◯◯）

■ 話したいことを、下記Notionページの各アジェンダの「事前記入」欄へ
　ご記入ください（当日午前中まで／1分で終わります）
　→ （Notionページのリンク）

■ 前回からの持ち越し
　・（担当）：（内容／期限）
```

該当のない行・ブロックは丸ごと省略する。資料の提出は求めない。記入先はNotionに一本化し、スレッドに書くよう促さない。敬体で書く。

## 【厳守】

- **🟦 5. 今日決まったこと には一切書き込まない。** 0. の持ち帰り表で書けるのは 今回の進捗／共有・相談事項／ステータス の3列だけ（次回ページでは担当・内容・期限の転記のみ）。
- **🟩 と 🟨 には触れない。** 「🟩 経営・組織課題ボードの進捗確認（自動転記）」も触らない。
- **事業版のDB・ページには書き込まない。**
- 発言の要約はするが、言っていないことを補わない。発言者が特定できなければ「発言者不明」。
- 個別社員の評価・処遇に関する発言は残さない。
- 対応する発言がなければ空欄のまま（「特になし」と書かない）。
