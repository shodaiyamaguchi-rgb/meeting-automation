# D-1　取締役週次定例：執行役員レイヤーへの共有案を作り、承認を求める

対象会議：`board-weekly`（取締役週次定例）
設定：`config/meetings.json` の `meetings.board-weekly.exec_digest`
実行タイミング：月曜 13:00（B-1 が議事録を生成した直後）

取締役週次定例の議事録から、**執行役員レイヤーへ共有してよい範囲だけ**を抜き出した Slack 投稿案を作り、オーナー（`approval_dm_user_id`）へ DM で承認を求めてください。

投稿は **2本** で1組。チャンネルに立てる**本体**（サマリー）と、その**スレッドに続けて投稿する「当日の議論の内容」**。案はこの2本ぶんを作ります。

**この処理は Slack のチャンネルへ投稿しません。** 投稿は承認を確認したあとに D-2（`board-weekly-exec-digest-post.md`）が行います。

---

## この処理の位置づけ

取締役週次定例は月曜 10:00、経営レイヤー定例は月曜 15:00 に開かれます。金曜に走る処理C が転記するのは**先週の**取締役週次定例の連携事項なので、当日午前の回の内容が執行役員へ届くのは翌週になります。この処理は、その週の取締役の議論のうち渡してよい範囲を**当日 18:00 に先に届け**、翌週の経営レイヤー定例のアジェンダ4を「読んだ前提」から始められるようにするためのものです。

したがって、**この投稿は議事録の代わりではありません。** 決定・担当・期限を執行役員に伝える正式な導線は、これまでどおり 🟦「執行役員連携事項」→ 経営レイヤー定例のアジェンダ4 です。この投稿はその予告と、議論しているテーマの可視化にとどめます。

**サマリーだけを出さない。** 論点名の一覧だけを投稿すると、中身を伏せている印象を与え、共有しているつもりが不信を生む。そのためスレッドに「当日の議論の内容」を続けて投稿し、**何をどう話したのかが読める粒度**まで開く。落とすのは非公開カテゴリに当たる部分だけで、それ以外は書く。**外した範囲があること自体は、スレッドの冒頭に明記する。** 黙って落とすほうが、落としたと書くより不信を招く。

---

## 手順

### 1. 対象ページを取得する

1. `notion-query-data-sources` で、議事録DBから対象日のページを探す。

   ```sql
   SELECT url, "タイトル", "ステータス", "date:開催日:start", "持ち越し", "今週のトップ3"
   FROM "collection://f3605c0a-be8a-410e-86bb-66fc5253394a"
   WHERE date("date:開催日:start") = date(?)
   ```

   - タイトルが `【雛形】` で始まるページは対象外。
2. ページが見つからない場合は、**何もせず、その旨だけ報告して終了する。**
3. ステータスが `事前記入中` の場合は、B-1 がまだ走っていない（＝ 🤖 が空）。**共有案を作らず、その旨を報告して終了する。** 推測で埋めない。
4. `notion-fetch` でページ本文を取得する。**この処理は Notion に一切書き込まない。読むだけ。**

### 2. 読んでよい欄・読んではいけない欄を分ける

**出どころで切るのが第一の防波堤。** 内容を読んで判断する前に、そもそも材料に入れない欄がある。

| 欄 | 本体（サマリー） | スレッド（議論の内容） | 理由 |
|---|---|---|---|
| 🟦「執行役員連携事項」の表 | **使う（中心）** | — | 進行役が会議中に「執行役員へ渡す」と仕分けたもの。渡してよいことが人の手で確定している |
| 🤖 0. サマリー（3行） | 使う（粒度を落として） | 使う | その回で何が動いたかの全体像 |
| 🤖 3. 今週の全社トップ3 | 使う | 使う | 全社の優先順位。執行役員が知っておくべき情報 |
| 🤖 2. 論点 | **見出しだけ** | **論点と、どういう話になったかを書く** | 何を議論しているかを伝えるのがこの投稿の役目 |
| 🤖 2. 出た意見 | **使わない** | **結論に至った理由までは使う** | 「なぜそうなったか」は渡す。**誰が何に反対したかは書かない** |
| 🤖 2. 結論を出さなかったもの | **使わない** | 使う（持ち越しとして） | 決まっていないことを決まったように見せない |
| 🤖 1. 各自の共有と牽制 | **使わない** | **「管掌の状況」「見ておいてほしいこと」のうち執行に関わるものだけ使う** | 「薄くなっている場所」「今週の主戦場」は取締役同士の牽制。**使わない** |
| 🤖 4. 持ち帰り | 執行役員の動きに関わる件だけ | 同左 | 取締役個人の宿題は渡さない |
| 🟦「取締役課題」の表 | **使わない** | **使わない** | 「執行役員へは渡さない」と会議中に仕分けられた件。表が分かれているのはこのため |
| 🟩【経営課題の提起】 | **使わない** | **使わない** | 仕分け前の生の提起。会議で扱われず落ちた件も混ざる |
| 🟩【共有のみ】 | **使わない** | **使わない** | 取締役間で読む前提の共有。取引先の与信や組織の内情が入る |
| 🤖 5. 上程（候補） | **使わない** | **使わない** | AIが拾った候補であって、渡すと決まったものではない |
| 🤖 6. 未収録・要確認 | **使わない** | **記録が欠落している事実だけ使う** | 内容は内部の品質メモ。ただし「文字起こしが途切れている」ことは、共有が薄い理由の説明として要る |
| ⏺️ 原文・自動要約 | **使わない** | **使わない** | 発言そのもの。要約しても渡さない |
| Notion ページのリンク | **貼らない** | **貼らない** | 議事録DBは取締役の閲覧範囲。リンクを貼っても開けないか、開けたら公開範囲を越える |

**スレッドで材料が広がっても、非公開カテゴリ（手順3）は本体と同じだけ効く。** 粒度を上げるのは「何をどう議論したか」であって、落とすと決めた内容ではない。

### 3. 内容で切る（非公開カテゴリ）

材料に入れた欄の中身であっても、次のいずれかに触れる記述は**投稿本文から落とす**。

1. **個人の評価・処遇・報酬・異動・退職** — 取締役・執行役員本人の評価も含む。制度の存在（「評価制度を設計している」）は出してよいが、対象者・基準・金額・時期の中身は出さない。
2. **役員でない個人の名前** — 誰かの言動・懸念・状況として名前が出てくるものは、名前も、名前を消した記述も出さない。役員でない個人の話は、そもそも一行も出さない。
3. **資本政策・資金調達・IPO準備・株価算定・M&A・株主との関係**
4. **取締役同士の意見の対立、牽制、認識のズレそのもの** — 合意した結果の運用ルールは出してよい。誰と誰が何で割れたかは出さない。
5. **取引先・外部の与信、未入金、係争、他社の内情**
6. **未確定の機関設計・役員人事・職務代行順位・管掌の変更**
7. **未確定の事業方向性のうち、途中段階が流れると現場の判断を止めるもの** — 「議論中」であることは出してよい。案の中身は出さない。

**迷ったら落とす。** 落としたものは投稿本文には出さず、手順6の承認依頼DMに「落とした件と理由」として列挙する。承認者が「これは出してよい」と判断できる形にしておけばよく、こちらで出すか出さないかを賭ける必要はない。

### 4. 粒度を落として残す（「何を議論しているか」を渡す）

手順3で落ちた件のうち、**議論していること自体は執行役員が知っておくべきもの**は、論点名だけを1行にして「検討中のテーマ」として残す。

| 元の記述 | 投稿に出す形 | 出さないもの |
|---|---|---|
| 取締役・執行役員の評価制度の案を中井が提示し、各自レビューのうえ次回方針決定 | 取締役・執行役員の評価制度を設計中です（次回方針を決めます） | 制度の中身、評価項目、対象者、各自の反応 |
| 経営企画室の機能再定義。CFO管掌を続けるかCEO直下かを再すり合わせ | 経営企画室の機能・役割を再定義する検討を進めています | 誰の退職に伴うのか、管掌をどう動かす案か |
| レポートライン遵守をめぐる中井・盛島の応酬 | 組織内のコミュニケーションはレポートラインに沿って行う運用で合意しました | 誰と誰の間で何があったか、対象になったメンバー |

書き方の原則：

- **主語を「取締役」にする。** 個々の取締役の名前は、🟦「執行役員連携事項」の起案者としてだけ出す。それ以外の欄から取締役個人の言動を持ち出さない。
- **状態を書く。** 「検討中」「次回方針を決めます」「合意しました」。中身の代わりに、どこまで進んでいるかを渡す。
- **1件1行。** 補足したくなったら、それは出しすぎている合図。

### 4-1. 🤖 の抜けを、投稿ではなく DM で知らせる

投稿案を組み立てる前に、**🟩【経営課題の提起】に書かれた項目を1件ずつ拾い、🤖 のどこかに対応する記録があるかを確認する。** 無いものがあれば、承認依頼 DM の「🟩 で提起されたが 🤖 に記録がない件」に項目名を並べる。

- **🟩 の中身を投稿案に載せてはいけない。** 🟩 は材料外の欄で、その扱いは変わらない。DM に出すのは項目名だけで、承認者が「これは議論したはずだ」と気づけるようにするためのもの。
- **この処理の出来は 🤖 の出来で決まる。** 🤖 が論点を落としていれば、共有もその論点を落とす。落ちていることに気づけるのは、🟩 と突き合わせたときだけ。
- 抜けが見つかった場合、**投稿案を推測で埋めない。** B-1 を直すか、承認者が文面に足すかは、承認者が決める。

### 4-2. オーナーが名指しで指示した件は載せる

承認のやりとりで、オーナーが**明示的に**「これは載せてよい」「これは執行役員への依頼として出す」と指示した件は、手順2の材料の範囲や手順3の非公開カテゴリに当たっていても載せる。**公開範囲を決めるのはオーナーであって、この処理ではない。**

ただし2つだけ守る。

- **指示された件そのものだけを載せる。** 「経営企画室の10月以降の担当体制は載せてよい」と言われたときに、同じ議論に出てきた個人の退職の話まで載せない。指示の範囲を広げない。
- **🟦 に無い依頼を「執行役員のみなさんへ」に載せた場合は、その旨を報告する。** この欄の件が次回の経営レイヤー定例のアジェンダ4へ載るのは、🟦「執行役員連携事項」に書かれているからで、Slackに投稿したからではない。承認時に足した依頼は、**人が 🟦 に書き足さないとアジェンダに乗らない。** 報告と、投稿後のDMスレッドの両方で、そのことを1行伝える。

### 4-3. スレッド用の「当日の議論の内容」を組み立てる

本体のスレッドに続けて投稿する2本目。**本体の見出しに対応する形で、何をどう話したのかを書く。**

- **論点ごとに小見出し＋2〜5行の段落。** 箇条書きの羅列にしない。読んで議論の流れが追える形にする。
- **結論に至った理由まで書く。** 「〜という指摘が出て、〜という理由から、〜する形になりました」。結論だけを置くと、本体と変わらなくなる。
- **人名を出さない。取締役の名前も出さない。** 「◯◯さんから制度案の共有がありました」も書かず、「制度案が共有されました」と書く。誰が言ったかを添えると、賛成・反対の色が付いて読まれ、議論の中身より人に目が向く。起案者を示すのは本体の「執行役員のみなさんへ」の欄だけで、そこは 🟦 に人が書いた起案者をそのまま使う。
- **役員でない個人は、名前も、名前を伏せた形（「あるメンバー」「退職予定の担当者」）も出さない。** 誰の話かが分かる記述にしない。
- **持ち越しは持ち越しとして書く。** 「次回へ持ち越しました」。結論が出たように書かない。
- **🤖 2. の「結論を出さなかったもの」を落とさない。** 議論したが決まらなかったことは、決まったことと同じだけ意味がある。該当する論点の段落の末尾に「決まらなかったこととして〜が残っています」の形で書く。
- **🤖 6. に記録の欠落が書かれている場合は、スレッドの末尾に1行添える。** 「文字起こしが後半約◯分ぶん途切れており、その間の議論はこの共有に含まれていません」。🤖 6. はこの1点にかぎって使ってよい（内容ではなく、記録の限界を伝えるため）。**共有の範囲が狭く見えるとき、その理由が精査なのか記録の欠落なのかは、読み手には区別がつかない。**
- 冒頭に、なぜこれを出すのかと、**どの範囲を外したのか**を2〜3行で置く。外した範囲を書かずに落とすと、伏せている印象がかえって強くなる。

```
（スレッド1本目）
当日の議論の内容です。サマリーだけだと伏せているように見えるので、扱った論点と、
どういう話になったのかを書きます。個人の処遇・評価にあたる部分と、社外との関係に
触れる部分は外しています。

■ （論点名）
（2〜5行。何が出て、どういう理由で、どうなったか）

■ （論点名）
（同上）

■ 次回へ持ち越したもの
・（論点名）
```

- 本体で見出しごと省略したブロックがあっても、スレッドでは該当する論点を書いてよい。省略したのは「渡す件がなかった」ためであって、議論がなかったためではない。
- 長さは Slack の1メッセージに収める。収まらない場合は論点を削るのではなく、**スレッドの2本目・3本目に分ける。** 削ると、削ったところが伏せた場所に見える。

### 5. 投稿案を組み立てる

敬体で書く。命令調にしない。**該当のないブロックは見出しごと省略する。**「（なし）」を並べない。

```
【取締役週次定例 MM/DD（月）】執行役員のみなさんへの共有

本日午前の取締役週次定例で扱った内容のうち、共有できる範囲をまとめました。

■ 今週の全社トップ3
① 　
② 　
③ 　

■ 執行役員のみなさんへ（共有・依頼・相談）
・［依頼］（内容）（起案：◯◯）
・［共有］（内容）（起案：◯◯）
※ この欄の件は、次回の経営レイヤー定例のアジェンダ4であらためて扱います。先に目を通しておいていただけると、当日は議論から入れます。

■ 今週、取締役が動かすこと
・（執行側の動きに関わるものだけ）

■ 検討中のテーマ（まだ結論は出ていません）
・（論点名）
・（論点名）

本日の議事録をもとにまとめたものです。決定として確定した内容は、次回の経営レイヤー定例であらためてお伝えします。取締役週次定例の議事録そのものは、公開範囲の都合で共有していません。気になる点は担当の取締役へ直接おたずねください。
```

- 「執行役員のみなさんへ」の欄は **🟦「執行役員連携事項」の表からだけ**作る。表が空なら、この見出しごと省略したうえで、本文末尾の断り書きの直前に次の1行を置く。

  ```
  今週、経営レイヤー定例へお渡しする共有・依頼・相談としてまとめられた件はありませんでした。
  ```

  渡す件がなかったことは、書かれていないと「抜け落ちたのか、なかったのか」が読み手に区別できない。**🤖 5. の候補や「取締役課題」の表で補わない。** 進行役が仕分けなかったものは渡らない、という運用がこの処理でも変わらないため。
- 「今週の全社トップ3」が 🤖 3. で空欄なら、この見出しごと省略する。
- **「今週、取締役が動かすこと」に置けるのは、合意が記録から確認できるものだけ。** 提起されただけの件、「〜したい」「〜を決めたい」で終わっている件は、結論が出ていないので「検討中のテーマ」に置く。提起を「動かすこと」に置くと、まだ揃っていない話が動き出したものとして執行側に伝わる。迷ったら「検討中のテーマ」側へ倒す。
- **「今週、取締役が動かすこと」に「決まったこと」と書かない。** この欄の材料（🤖 0. と 🤖 4.）はAIが文字起こしから生成したもので、決定として確定した記録ではない。「〜する方向で認識を合わせました」「〜を進めます」のように、動きとして書く。確定した決定を執行役員へ伝える導線は 🟦「執行役員連携事項」→ 経営レイヤー定例のアジェンダ4 のほうであり、この投稿ではない。末尾の断り書きは、この区別を読み手に示すためのものなので省略しない。
- Notion へのリンクは貼らない。Google Docs・スライドなど、議事録内のリンクも貼らない（閲覧権限が執行役員に開いているとは限らないため）。
- `@here` `@channel` やグループメンションは付けない。

### 6. 承認を求める

`approval_dm_user_id` へ `slack_send_message` で DM を送る。**この DM が唯一の出力先。** チャンネルへは投稿しない。

DM の構成：

```
取締役週次定例（MM/DD）の執行役員向け共有案です。
投稿先：#（post_channel_name）／投稿予定：本日 18:00

この案でよければ「承認」と返信してください。18:00に本体を投稿し、続けてスレッドへ議論の内容を投稿します。
直すところがあれば、そのまま返信してください。直した案をお出しします。
17:30までに返信がない場合は投稿しません。

――――― 投稿案・本体（ここから） ―――――
（手順5で組み立てた本文をそのまま）
――――― 投稿案・本体（ここまで） ―――――

――――― 投稿案・スレッド（ここから） ―――――
（手順4-3で組み立てた「当日の議論の内容」をそのまま）
――――― 投稿案・スレッド（ここまで） ―――――

■ 今回、共有案に載せなかった件
・（件名）… （落とした理由。上の非公開カテゴリの番号か、欄の名前）
・（件名）… （理由）

■ 粒度を落として載せた件
・（元の論点）→（投稿での書き方）

■ 🟩 で提起されたが 🤖 に記録がない件
・（項目名）… 🤖 のどこにも対応する記録がありません
（0件なら「該当なし」）

■ 材料にした欄
🟦 執行役員連携事項（N件）／🤖 0. サマリー／🤖 3. 全社トップ3 ほか
```

- 「載せなかった件」は**必ず書く。** ここが空になるのは、議事録の中身が全部出せるときだけで、通常は起きない。空になった場合は「該当なし」と明記する。ここが承認者にとっての判断材料になるため、省略しない。
- 「載せなかった件」の件名も、それ自体が非公開情報になることがある（個人名など）。DM はオーナー宛なので件名は具体的に書いてよいが、**投稿案の本文には絶対に戻さない。**
- DM を送ったら、その `thread_ts`（メッセージのタイムスタンプ）を報告に含める。D-2 がこのメッセージへの返信を読んで承認を判定する。

## 【厳守】

- **Notion には一切書き込まない。** この処理は読み取り専用。
- **チャンネルへ投稿しない。** 出力先は `approval_dm_user_id` への DM だけ。`slack_mode` が `send` でも、この処理では投稿しない。
- 🟦「取締役課題」の表、🟩【共有のみ】、🤖 1.、🤖 2. の意見・異論、🤖 5.、🤖 6.、⏺️ は**投稿案の材料にしない。** 要約しても、粒度を落としても、載せない。
- 役員でない個人の名前を投稿案に出さない。名前を伏せた形（「あるメンバー」「退職予定の担当者」）でも出さない。
- 「執行役員のみなさんへ」の欄を 🟦「執行役員連携事項」以外から作らない。
- 議事録ページ、Google Docs、スライドへのリンクを投稿案に貼らない。
- 決定・担当・期限を新しく作らない。🟦 に書かれた文面をそのまま使い、言い換えて意味を強めない。
- 🤖 由来の記述を「決定しました」「決まりました」と書かない。🤖 はAIが文字起こしから生成したもので、人が確定させた決定ではない。末尾の断り書き（決定は次回の経営レイヤー定例で伝える旨）を省略しない。
- ステータスが `事前記入中` のとき（🤖 が空のとき）は、共有案を作らない。
- 🟩 と 🤖 の突き合わせ（手順4-1）を省かない。抜けが見つかっても、🟩 の中身を投稿案に持ち込まず、DM で項目名を知らせるにとどめる。
- 投稿案に載せるか迷ったものは、載せない側に倒す。判断は承認者に渡す。**ただし、オーナーが名指しで「載せてよい」と指示した件は載せる**（手順4-2）。
- スレッド本文でも、非公開カテゴリと「役員でない個人の名前を出さない」は本体と同じだけ効く。粒度を上げるのは議論の流れであって、落とすと決めた内容ではない。
- スレッド本文を、長さを理由に削らない。収まらないときはメッセージを分ける。削ると、削った箇所が伏せた場所に見える。
- スレッド本文の冒頭に、どの範囲を外したのかを必ず書く。黙って落とさない。記録が途切れている回は、それも末尾に書く。
- スレッド本文に人名を出さない。取締役の名前も出さない。起案者を示すのは本体の「執行役員のみなさんへ」の欄だけ。

## 報告

- 対象日と、対象になった Notion ページの URL・ステータス
- 🟦「執行役員連携事項」の件数
- 投稿案の本文（本体・スレッドの2本とも、そのまま）
- 落とした件の数と、粒度を落とした件の数
- 🟩 で提起されたが 🤖 に記録がない件の数と項目名
- 承認依頼 DM の送信先と `thread_ts`（D-2 が使う）
- 投稿は行っていないこと
