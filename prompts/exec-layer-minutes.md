# B-2　経営レイヤー定例：会議後の議事録生成とSlack投稿

対象会議：`exec-layer`（経営レイヤー定例）
実行タイミング：会議終了の1時間後／翌朝08:00のリトライ

経営レイヤー定例の議事録を作成し、Slackへ展開してください。**対象日**（実行時コンテキストの `TARGET_DATE`）に開催された回が対象です。

この処理は 2026-08-24 の回で手動実行して検証済み。そこで分かった実務をこのプロンプトに落としてある。

---

## 手順

### 1. 文字起こしを取得する

1. Google Calendar の `list_events` で、対象日（00:00〜23:59 JST）の予定を取得する。タイトルに `calendar_title_keyword`（`経営レイヤー定例mtg`）を含む予定を探す。
2. 予定が見つからない場合は、**その旨だけ報告して終了する。** Notionには何も書かない。
3. 予定の `attachments` から文字起こしを探す。Meetは通常2つ添付する。

   | 添付名 | 中身 | 使う |
   |---|---|---|
   | `Gemini によるメモ`（Google Docs） | 概要／決定事項／次のステップ／詳細 ＋ **文字起こし本文** | **これを使う** |
   | `… Recording`（動画） | 録画 | 使わない |

   Meetの「Gemini によるメモ」は、1つのドキュメントの中に要約と逐語の文字起こしの両方が入っている。別ファイルの文字起こしを探しに行く必要はない。
4. 添付が見つからない場合は、Google Drive の `search_files` でフォールバックする。

   ```
   title contains '経営レイヤー定例' and modifiedTime > '{{対象日}}T00:00:00+09:00'
   ```
5. `read_file_content` で本文を取得する。**文字起こしがまだ生成されていない場合は、その旨だけ報告して終了する。** 翌朝のリトライで再実行される。
6. ドキュメントのURLを控える（あとでプロパティに入れる）。

### 2. Notionの対象ページを取得する

1. 対象日のページを探す。`notion-query-data-sources` のSQLはこのDBでタイムアウトすることがあるので、**まず `notion-search` を使う**。

   ```
   notion-search: query="経営レイヤー定例 議事録",
                  data_source_url="collection://232b1cc0-f19e-430d-a8b7-481a481560ce"
   ```

   タイトルが `YYYY-MM-DD 経営レイヤー定例` の形で対象日と一致するページを選ぶ。`【雛形】` で始まるページは対象外。**雛形には絶対に書き込まない。**
2. ページが見つからない場合は、**新規作成せず、その旨を報告して終了する。** ページの作成は A-2 の責務。
3. ステータスが `記録済` または `確認済` なら、**二重実行を避けて終了する。** 対象は `事前記入中` のページのみ。

   このDBのステータスは `事前記入中` / `記録済` / `確認済` の3つ。**「自動生成済」は存在しない**（取締役週次定例側の語彙とは違う）。
4. `notion-fetch` でページ本文を取得する。以降の置換に使うので、取得した本文はそのまま保持しておく。
5. 各アジェンダの 🟩 事前記入、🟦 5. 今日決まったこと、🟨 6. を読み込む。**すべて生成の材料としてのみ使う。書き換えない。**

### 3. アジェンダ1〜4の「🤖 議論の記録」だけを埋める

ページの構造は次のとおり。**埋めるのは 🤖 の4箇所だけ。**

```
■ 凡例
🟩 共有しておきたいこと                    ← 読むだけ
0. 前回の決定と持ち帰りの確認
   ▸ 🟦 前回の持ち帰り                     ← 触らない
1. 執行役員からの相談
   ▸ 🟩 事前記入                           ← 読むだけ
   ▸ 🤖 議論の記録                         ← ここを埋める
2. 組織状態の報連相と、そこから見える兆し
   ▸ 🟩 事前記入 ／ ▸ 🤖 議論の記録        ← 🤖 を埋める
3. 今後起きえる経営課題の提起
   ▸ 🟩 事前記入 ／ ▸ 🤖 議論の記録        ← 🤖 を埋める
4. 取締役からの共有・依頼・相談
   ▸ 🟩 事前記入 ／ ▸ 🤖 議論の記録        ← 🤖 を埋める
🟦 5. 今日決まったこと                     ← 触らない
🟨 6. 経営課題ボードの更新                 ← 触らない
```

各 🤖 の形式は雛形のまま変えない。

- **1. 執行役員からの相談** — 箇条書き。`- 相談者：` `- 論点：` `- 出た意見：` の3行を1件として、**🟩 事前記入に書かれた件ごとに繰り返す。** 事前記入の順に並べる。事前記入にあるが会議で扱われなかった件は、論点だけ書き「この場では扱わなかった」と残す。
- **2. 組織状態の報連相と、そこから見える兆し** — 表（論点／出た意見／この場で出た手・次の動き）。
- **3. 今後起きえる経営課題の提起** — 表（論点／出た意見／課題ボードに起票するか）。
- **4. 取締役からの共有・依頼・相談** — 表（件名／出た意見／担当・期限）。

**対応する発言がなければ、その 🤖 は雛形のまま空欄で残す。** 2026-08-24 の回ではアジェンダ3が空だった（事前記入も議論もなかった）。空欄のまま残すのが正しい挙動で、他のアジェンダの内容を移してきて埋めてはいけない。

議論が別のアジェンダの時間に出た場合は、**事前記入がある側のアジェンダに書く。** 例：アジェンダ1の相談から始まった数値目標の議論が、アジェンダ4に中井の事前記入として存在するなら、結論はアジェンダ4に書き、アジェンダ1には「詳細はアジェンダ4」と残す。

### 4. ページに書き込む

`notion-update-page` の `update_content` を使う。`content_updates` に、埋める 🤖 ごとに1件ずつ渡す。

**この雛形のサブ欄はトグル見出し（`### 🤖 議論の記録 {toggle="true"}`）で、中身はタブでインデントされている。** 表は Notion の出力にあわせて次の形にする。開始タグと終了タグだけタブを付け、`<tr>` / `<td>` は行頭から書く。

```
### 🤖 議論の記録 {toggle="true"}
→タブ<table header-row="true">
<tr>
<td>論点</td>
...
</tr>
→タブ</table>
```

`old_str` は取得した本文からそのまま切り出す。**`</table>\n### 🤖 議論の記録` はページ内に4回出るので、`old_str` には必ずその 🤖 表の列見出し（`この場で出た手・次の動き` / `課題ボードに起票するか` / `件名` など）まで含めて一意にする。**

**🟩 と 🟦 のデータ行を `old_str` に含めない。** 見出し行と `<table>` / `</table>` の行だけを触れば、表の中身に触らずに済む。事前記入にはコメントスレッド（`<span discussion-urls="...">`）やSlackリンクが埋まっていることがあり、写し間違えると壊れる。

### 5. プロパティを更新する

`notion-update-page` の `update_properties` で以下を設定する。

| プロパティ | 値 |
|---|---|
| `ステータス` | `記録済` |
| `参加者` | 文字起こしで発言が確認できた人。`["久保","中井","盛島","山口","古本","多加谷","藤本","福有"]` から選ぶ |
| `欠席` | **欠席が明言された人だけ。** 発言がないだけの人は入れない |
| `決定事項` | 🟦 5. の表を1行に転記する。**要約はするが、書かれていない決定を足さない** |
| `関連する課題ボード#` | 🟦 5. と 🟩 の「課題ボード#」列に書かれた番号。空なら空のまま |
| `Zoom録画` | 「Gemini によるメモ」のURL |

**`認識ギャップ` と `次回への持ち越し` は空のままにする。** この2つは 🟦 の「8. 認識ギャップ」「6. 持ち帰り」を読み取って埋める設計だったが、現行の雛形にその欄がない。読み取り元がないままAIが判断して埋めると、決定・担当・期限をAIに書かせないという方針を破ることになる。人が必要と判断したときに手で入れる。

**出欠の扱いに注意。** 発言がないことは欠席の証拠にならない。57分の会議で一度も発言せず、第三者として言及されているだけの参加者がいた場合、**参加者にも欠席にも入れず、報告で「出欠が確認できなかった」と挙げる。** 推測で欠席にしない。

### 6. 書き込みを検証する

`notion-fetch` でページを再取得し、次を確認する。**ここが本処理でいちばん重要な確認。**

- 🟦 5. 今日決まったこと の表が、書き込み前と1文字も変わっていないこと。担当者のメンション（`<mention-user url="user://…"/>`）が消えていないこと
- 🟦 前回の持ち帰り（0.）と 🟨 6. が変わっていないこと
- 各アジェンダの 🟩 事前記入が変わっていないこと。コメントスレッドの `discussion-urls` が消えていないこと
- 🤖 以外の見出し・凡例の表・区切り線が変わっていないこと

差分があれば、Slackへは投稿せず、何が変わってしまったかを報告する。

### 7. Slackへ投稿する

`slack_channel_id` が空の場合は投稿せず、本文を出力して終了する。

```
【経営レイヤー定例 MM/DD】議事録ができました → （Notionリンク）
・決まったこと：（🟦 5. から転記）
・課題ボードの更新が必要な件：#（オーナー名）
※ 誤りがあればNotionを直接修正してください（スレッドで議論しない）
```

**この2本だけにする。** 引き継ぎ書 §5-4 のフォーマットにある「持ち帰り」「決まらなかったもの」は、読み取り元の欄が現行の雛形に存在しないため落とす。空の行を並べたり、AIが議論から拾って埋めたりしない。

- 🟦 5. が空欄のまま会議が終わっていた場合は、「決まったこと」の行に「（Notionの 🟦 5. が未記入です）」と書く。**AIが議論から決定事項を作らない。**
- 🟨 6. が未記入なら「なし（🟨 6. が未記入のため）」と書く。
- 出欠が確認できなかった人がいた場合は、`※ ◯◯の出欠が文字起こしから確認できませんでした。Notionの参加者欄をご確認ください。` を足す。

---

## 【厳守】

- **🟦 の欄（0. 前回の持ち帰り／5. 今日決まったこと）には一切書き込まない。** 会議中に進行役が入力済みのため、上書きも補完もしない。Slack投稿はこれらの欄を読み取って転記するだけ。
- **🟩 の事前記入欄も上書きしない。** 読み取り専用として扱う。要約もしない。
- **🟨 9.（現行の雛形では 6.）はオーナーの欄。触らない。**
- 発言の要約はするが、言っていないことを補わない。
- 発言者が特定できない発言は「発言者不明」と明記する。
- **個別社員の評価・処遇に関する発言は議事録に残さない。** 1on1でのフィードバック内容、特定個人の退職の見込み、マネージャー適性の評価などが文字起こしに含まれていても書かない。制度としての論点（退職面談を仕組み化する、評価制度を見直す）は書いてよい。
- アジェンダの枠に対応する発言がなければ空欄のままにする（推測で埋めない）。

## 報告

最後に、次の内容を標準出力へ報告する。

- 対象日と、対象になったNotionページのURL
- 文字起こしの取得元（カレンダー添付／Drive検索／取得できず）
- 埋めた 🤖 と、空欄のまま残した 🤖
- 更新したプロパティと、空のままにしたプロパティ
- 🟩 / 🟦 / 🟨 の検証結果
- 出欠が確認できなかった人
- 除外した発言があればその旨（内容は書かない。「個別社員の処遇に関する発言を除外した」だけでよい）
- Slack投稿の有無（未投稿ならその理由）
