# meeting-automation

ABABA Inc. の2つの会議体（取締役週次定例／経営レイヤー定例）について、議事録の生成とSlack展開を自動化する。あわせて、取締役週次定例の内容を執行役員レイヤーへ共有できる範囲だけ切り出して展開する処理を持つ。

設計の出典は引き継ぎ書「会議議事録の自動化（取締役週次定例／経営レイヤー定例）v1.1」。

## 構成

```
meeting-automation/
├── prompts/
│   ├── _shared-rules.md          # 全処理に共通するルール（4マーク凡例・書き込んでよい欄・失敗時の振る舞い）
│   ├── board-weekly-prep.md      # A-1 取締役週次定例：金曜朝の準備
│   ├── board-weekly-minutes.md   # B-1 取締役週次定例：会議後の議事録生成とSlack投稿
│   ├── exec-layer-prep.md        # A-2 ＋ C 経営レイヤー定例：準備と取締役提案の転記
│   ├── exec-layer-minutes.md     # B-2 経営レイヤー定例：会議後の議事録生成とSlack投稿
│   ├── board-weekly-exec-digest.md       # D-1 執行役員レイヤーへの共有案と承認依頼
│   └── board-weekly-exec-digest-post.md  # D-2 承認を確認して18:00に予約投稿
├── config/
│   └── meetings.json             # Notion ID・Slackチャンネル・参加者
├── run.sh                        # プロンプトを組み立てて claude -p に流す
├── crontab                       # cronで動かす場合のスケジュール定義（未登録）
├── ROUTINES.md                   # claude.ai のルーティンとして登録する手順とプロンプト全文
└── logs/                         # 実行ログ（gitignore）
```

処理の中身は「Notionを読んで、判断して、書く」という自然言語処理のため、決定論的なコードには落とさず、プロンプトを外部ファイルに切り出して `claude -p` で実行する。文言は運用しながら `prompts/` を直して調整する。

## 使い方

```bash
./run.sh board-weekly-prep                 # A-1
./run.sh board-weekly-minutes              # B-1（本日の回）
./run.sh board-weekly-minutes yesterday    # B-1（前日の回。翌朝のリトライ）
./run.sh exec-layer-prep                   # A-2 ＋ C
./run.sh exec-layer-minutes 2026-08-24     # B-2（日付を指定して再実行）
./run.sh board-weekly-exec-digest          # D-1（共有案を作ってオーナーへDM）
./run.sh board-weekly-exec-digest-post     # D-2（承認を確認して本体＋スレッドを投稿）

DRY_RUN=1 ./run.sh board-weekly-minutes    # 組み立てたプロンプトを表示するだけ
```

`run.sh` は `prompts/_shared-rules.md` ＋ 実行時コンテキスト（対象日・`config/meetings.json`）＋ 個別プロンプトを連結して `claude -p` に渡す。同じプロンプトの多重起動は `flock` で防いでいる。

必要なMCP：Notion / Slack / Google Calendar / Google Drive。

## 議事録ページに書き込んでよい場所

ページの各欄には、誰がいつ埋めるかを表すマークが付いている。

| マーク | いつ | 誰が | 自動化の扱い |
|---|---|---|---|
| 🟩 | 会議前 | 各自 | 読み取り専用 |
| 🟦 | 会議中 | 進行役 | 一切書き込まない |
| 🤖 | 会議後 | 自動 | ここだけを書き込む |
| ⏺️ | 会議後 | 自動 | 文字起こしの原文と自動要約を加工せず格納する |
| 🟨 | 会議後 | オーナー（山口） | 対象外 |

決定内容・実行担当・期限は認識がずれやすく、AIが推測で埋めると誤った決定が一次情報として残る。そのため 🟦 は意図的に自動生成の対象外にしている。**初回テスト時は、🤖 と ⏺️ だけが埋まり 🟦 が空のままであることを必ず確認すること。**

## 雛形に加えた変更（2026-08-25）

取締役週次定例の雛形ページに、**🟦 会議中の仕分け（会議中／進行役が記入）** のトグルを追加した。会議で挙がった件を、進行役が会議中に2つに仕分ける。

| 表 | 列 | 行き先 |
|---|---|---|
| 執行役員連携事項 | 起案者 / 種別（共有・依頼・相談）/ 内容 | 次回の経営レイヤー定例のアジェンダ4へ転記される（処理Cの読み取り元） |
| 取締役課題 | 起案者 / 内容 / 次にどうするか | 取締役の中で持つ。**執行役員へは渡らない** |

執行役員連携事項の列は、経営レイヤー定例のアジェンダ4「取締役からの共有・依頼・相談」の 🟩 事前記入表と同じ形にしてある。処理C はここを1対1で転記すればよく、内容を組み立て直す必要がない。

**区分列を持つ1つの表ではなく、表を2つに分けた。** 1つの表に区分列を持たせると、行の読み違いがそのまま「渡すつもりのなかった件が執行役員に届く」になる。表が分かれていれば、処理C は片方の表しか読まないという書き方ができ、構造として取り違えようがない。

**この欄を足した理由。** 次回の経営レイヤー定例へ渡す提案の出どころが、これまで 🤖 5.上程（AI生成）か 🟩【経営課題の提起】（事前記入）しかなかった。どちらも「取締役がこの場で執行役員へ渡すと決めたもの」ではない。処理C はそれを執行役員の見える場所へ書き込むため、AIの推測が混ざると、決めていない提案が執行側に届く。会議中に進行役が書いたものだけを渡す形にして、そこを切った。

あわせて雛形側を3か所直した。

- ページ冒頭の流れの表に「当日（会議中）／進行役／🟦 のトグルで、挙がった件を執行役員連携事項と取締役課題に仕分ける」の行を追加
- 🟩【経営課題の提起】の説明を修正。「ここに書いた内容は次回の経営レイヤー定例で共有されます」→「ここに書いた内容の**うち、会議で「執行役員連携事項」に仕分けられたもの**が共有されます」。🟦 を経由するようになったため、元の文面のままだと嘘になる
- 🤖 5.上程 → 「5. 上程（候補）」に変更。AIが拾った候補であって確定ではなく、進行役が 🟦 への書き漏らしに気づくための控えである旨を明記

**処理C（A-2）の読み取り元は 🟩 ではなく 🟦「執行役員連携事項」の表になる。** 引き継ぎ書 §5-3 手順4 は「【経営課題の提起】この場で話したいこと」から抽出せよと書いているが、この変更で不要になった。「取締役課題」の表は読まない。A-2 の実装時に反映すること。

なお、雛形ページの中身を直しても、Notionの「テンプレートとして保存」に登録済みのテンプレートは自動では変わらない。登録済みのものがあれば、そちらも人が更新する必要がある。

## 経営レイヤー定例：雛形の新設とトグル化（2026-08-25）

**雛形ページを新設した。** `3c72fd3d-feaf-8132-886a-d605d12eebd3`（【雛形】YYYY-MM-DD 経営レイヤー定例）。2026-08-24 の回の構成をそのまま写し、中身を空にしたもの。引き継ぎ書に載っている `3c52fd3d-feaf-81ff-bbe9-fcd8cf668363` はゴミ箱にあるため使わない。A-2 はこの新しい雛形を複製元にする。

**サブ欄をトグル化した。** アジェンダ0〜4の 🟩 事前記入 と 🤖 議論の記録 を、トグル見出し（`### … {toggle="true"}`）にした。アジェンダ0〜6の並びは会議の進行順なのでそのまま残し、各アジェンダの中だけを畳めるようにしてある。マーク別にまとめる形は採らなかった。アジェンダの見出しが 🟩 側と 🤖 側の2か所に出てしまい、会議を上から進められなくなるため。

あわせて 0. の表を **「🟦 前回の持ち帰り（自動転記）」** に改名した。マークは 🟦 のままだが実際には A-2 が書き込む欄で、マークだけを見ると書き込み禁止の欄と区別がつかなかったため。取締役週次定例側の「前回の持ち帰り（自動転記）」と表記を揃えてある。**自動化が書き込んでよい 🟩 / 🟦 の欄は、見出しに「（自動転記）」が付いているかどうかで判断する。**（例外はアジェンダ4の 🟩 事前記入表だけ。人と処理Cが両方書く欄のため見出しを変えていない）

同じトグル化と改名を 2026-08-24 の実ページにも適用した。実データ（🟩 の事前記入、🟦 5.今日決まったこと、担当者メンション、コメントスレッド）はすべて保持している。トグル化は見出し行と `<table>` / `</table>` の行だけを触り、データ行は `old_str` に一切含めない方法で行った。Notionはトグル内の表を「開始タグと終了タグだけインデント、`<tr>` は非インデント」で出力するため、この2行だけで表をトグルの中へ移せる。

## 経営レイヤー定例の構成（決定事項・2026-08-25）

**2026-08-24 の回（`3c52fd3d-feaf-80c3-8003-facb0fa002b9`）の構成を正とする。** 引き継ぎ書 §4-2 ではなく、こちらに合わせて A-2 / B-2 を実装する。

- 🟦 は「5. 今日決まったこと」のみ。§4-2 にある 6.持ち帰り / 7.決まらなかったもの / 8.認識ギャップ の欄は持たない
- 課題ボードの更新は 🟨 6.（§4-2 では 9.）
- 各見出しの所要時間表記（18分など）は付けない

これに伴い、**B-2 のSlack投稿は「決まったこと」「課題ボードの更新が必要な件」の2本に絞る。** §5-4 のフォーマットにある「持ち帰り」「決まらなかったもの」は、読み取り元の欄がページに存在しないため落とす。プロパティ側の `次回への持ち越し` と `認識ギャップ` はAIに埋めさせない（決定・担当・期限をAIに書かせない方針を優先する）。

なお、雛形として登録されたページはまだない。`3c52fd3d-feaf-81ff-bbe9-fcd8cf668363` はゴミ箱にあり、8/24の回は実データが入った実ページなので、A-2 が複製元として使うには中身を空にした雛形ページを別途用意する必要がある。

## 執行役員レイヤーへの共有（D-1 / D-2・2026-09-06）

取締役週次定例の内容を、**毎週月曜18:00に執行役員レイヤーへ共有する**処理。2本で1組になっている。

| 処理 | 時刻 | やること |
|---|---|---|
| D-1 | 月 13:00 | 議事録から共有できる範囲を切り出し、投稿案をオーナーへDMする。**チャンネルへは投稿しない** |
| D-2 | 月 18:00 | 承認が返っていれば本体を投稿し、続けてスレッドへ議論の内容を投稿する。返っていなければ何もしない |

月曜の並びは 10:00 取締役週次定例 → 12:00 B-1（議事録生成）→ 13:00 D-1 → 15:00 経営レイヤー定例 → 17:00 B-2 → 17:30 承認の期限 → 18:00 D-2（承認確認と投稿）。

### なぜ経営レイヤー定例と別に要るのか

処理C が転記するのは**先週の**取締役週次定例の連携事項なので、当日午前の回が執行役員に届くのは翌週になる。D は、その週の議論のうち渡してよい範囲を当日18:00に先に届け、翌週の経営レイヤー定例のアジェンダ4を「読んだ前提」から始められるようにするもの。

**この投稿は議事録の代わりではない。** 決定・担当・期限を執行役員に伝える正式な導線は、これまでどおり 🟦「執行役員連携事項」→ 経営レイヤー定例のアジェンダ4。D はその予告と、議論しているテーマの可視化にとどめる。翌週の定例で同じ件が再び出るのは重複ではなく、この設計上の前提。

### 精査は2段構え

**1段目：出どころで切る。** 内容を読んで判断する前に、材料に入れる欄と入れない欄を決めておく。中心になるのは 🟦「執行役員連携事項」の表で、これは進行役が会議中に「執行役員へ渡す」と仕分けたもの、つまり**渡してよいことが人の手で確定している**唯一の欄。加えて 🤖 0. サマリー、🤖 3. 全社トップ3、🤖 2. の論点（見出しだけ）を使う。

材料に**入れない**のは、🟦「取締役課題」（渡さないと仕分けられた件）、🟩【経営課題の提起】（仕分け前の生の提起）、🟩【共有のみ】（取引先の与信や組織の内情が入る）、🤖 1. 各自の共有と牽制、🤖 2. の出た意見・異論、🤖 5. 上程候補（AIが拾った候補で、渡すと決まっていない）、🤖 6.、⏺️ 原文。

**内容の判断だけに頼らないのがこの設計の要点。** 「機微かどうか」をAIに読ませて切ると、判断を1回外すだけで渡さないと決めたものが執行側に届く。表が分かれていること自体を防波堤に使う。

**2段目：内容で切る。** 材料に入れた欄の中でも、次に触れる記述は落とす。個人の評価・処遇・報酬・異動・退職／役員でない個人の名前／資本政策・資金調達・IPO準備・株価算定・M&A／取締役同士の対立や認識のズレそのもの／取引先の与信・未入金・係争／未確定の機関設計・役員人事・職務代行順位／未確定の事業方向性の途中段階。

落としたもののうち「議論していること自体は知っておくべき」ものは、**論点名だけ**を「検討中のテーマ」として1行残す。中身の代わりに、どこまで進んでいるか（検討中／次回方針を決める／合意した）を渡す。

**迷ったら落とす。** 落とした件は投稿本文には出さず、承認依頼DMに「載せなかった件と理由」として並べる。ここが承認者の判断材料になるので、空欄にしない。

### 承認のしかた

D-1 がオーナー宛のDMに、投稿案・落とした件・粒度を落とした件・材料にした欄を1通で出す。

- **「承認」と返信** → D-2 が18:00に本体を投稿し、続けてスレッドへ議論の内容を投稿する
- **直したい点を返信** → D-2 が反映した案を同じスレッドへ出し直す。**投稿はしない**
- **返信しない** → 投稿されない。これが既定の動作

承認語が入っていても、後に修正指示や保留があれば投稿しない。どの案への承認か判別できない場合も投稿しない。承認の解釈を広げると、承認していない内容が執行役員へ届くため、ここは狭く倒してある。

修正指示であっても、非公開カテゴリを越える追加はD-2 が自分で行わない。載せられない理由を1行返し、判断をオーナーへ戻す。

### 投稿は本体とスレッドの2本（2026-09-06）

**サマリーだけを投稿しない。** 論点名の一覧だけを出すと、中身を伏せている印象を与え、共有しているつもりが不信を生む。本体をチャンネルに立てたあと、**同じスレッドに「当日の議論の内容」を続けて投稿する。**

```
（本体）
【取締役週次定例 MM/DD（月）】執行役員のみなさんへの共有

■ 今週の全社トップ3
■ 執行役員のみなさんへ（共有・依頼・相談）   ← 🟦「執行役員連携事項」からだけ作る
■ 今週、取締役が動かすこと                   ← 執行側の動きに関わるものだけ
■ 検討中のテーマ（まだ結論は出ていません）   ← 論点名だけ

（スレッド）
当日の議論の内容です。…（外した範囲を冒頭に明記）
■ 論点ごとに小見出し＋2〜5行。何が出て、どういう理由で、どうなったか
```

スレッドでは材料の範囲が広がり、🤖 2. の「なぜその結論になったか」と、🤖 1. の「管掌の状況」「見ておいてほしいこと」のうち執行に関わるものまで使う。**広がるのは議論の流れであって、落とすと決めた内容ではない。** 非公開カテゴリと「役員でない個人の名前を出さない」は本体と同じだけ効く。取締役の名前も、案を出した件に添えるだけで、**対立の当事者としては出さない。**

**スレッド本文の冒頭に、どの範囲を外したかを書く。** 黙って落とすほうが、落としたと書くより不信を招く。長さを理由に論点を削らない（削ると削った箇所が伏せた場所に見える）。収まらないときはメッセージを分ける。

該当のないブロックは見出しごと省略する。ただし 🟦 が空で「執行役員のみなさんへ」を省略したときは、**渡す件がなかったことを1行書く**（書かれていないと、抜けたのかなかったのかが読み手に区別できない）。**Notionページ・Google Docs・スライドへのリンクは貼らない**（議事録DBは取締役の閲覧範囲で、資料の権限も執行役員に開いているとは限らない）。`@here` `@channel` は付けない。

### オーナーが名指しで指示した件は載せる

公開範囲を決めるのはオーナーであって、この処理ではない。承認のやりとりで「これは載せてよい」「これは執行役員への依頼として出す」と明示された件は、材料の範囲や非公開カテゴリに当たっていても載せる。守るのは2つ。

- **指示された件そのものだけを載せ、範囲を広げない。** 「経営企画室の10月以降の担当体制は載せてよい」と言われたときに、同じ議論に出てきた個人の退職の話まで載せない。
- **🟦 に無い依頼を「執行役員のみなさんへ」に載せたら、その旨を伝える。** この欄の件が次回の経営レイヤー定例のアジェンダ4に載るのは 🟦「執行役員連携事項」に書かれているからで、Slackに投稿したからではない。承認時に足した依頼は、**人が 🟦 に書き足さないとアジェンダに乗らない。**
