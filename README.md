# meeting-automation

ABABA Inc. の2つの会議体（取締役週次定例／経営レイヤー定例）について、議事録の生成とSlack展開を自動化する。

設計の出典は引き継ぎ書「会議議事録の自動化（取締役週次定例／経営レイヤー定例）v1.1」。

## 構成

```
meeting-automation/
├── prompts/
│   ├── _shared-rules.md          # 全処理に共通するルール（4マーク凡例・書き込んでよい欄・失敗時の振る舞い）
│   ├── board-weekly-prep.md      # A-1 取締役週次定例：金曜朝の準備
│   ├── board-weekly-minutes.md   # B-1 取締役週次定例：会議後の議事録生成とSlack投稿
│   ├── exec-layer-prep.md        # A-2 ＋ C 経営レイヤー定例：準備と取締役提案の転記
│   └── exec-layer-minutes.md     # B-2 経営レイヤー定例：会議後の議事録生成とSlack投稿
├── config/
│   └── meetings.json             # Notion ID・Slackチャンネル・参加者
├── run.sh                        # プロンプトを組み立てて claude -p に流す
├── crontab                       # スケジュール
└── logs/                         # 実行ログ（gitignore）
```

処理の中身は「Notionを読んで、判断して、書く」という自然言語処理のため、決定論的なコードには落とさず、プロンプトを外部ファイルに切り出して `claude -p` で実行する。文言は運用しながら `prompts/` を直して調整する。

B-2 は 2026-08-24 の回に対して手動で一通り実行し、Notionへの書き込みとSlack投稿まで通している。そこで分かった実務（🟦 が 5. のみ、ステータスは `記録済`、Meetの「Gemini によるメモ」に要約と文字起こしが同居している、トグル内の表への書き込み方）をプロンプトに反映済み。他の3本は実データでの実行がまだ。

## 使い方

```bash
./run.sh board-weekly-prep                 # A-1
./run.sh board-weekly-minutes              # B-1（本日の回）
./run.sh board-weekly-minutes yesterday    # B-1（前日の回。翌朝のリトライ）
./run.sh exec-layer-prep                   # A-2 ＋ C
./run.sh exec-layer-minutes 2026-08-24     # B-2（日付を指定して再実行）

DRY_RUN=1 ./run.sh board-weekly-minutes    # 組み立てたプロンプトを表示するだけ
```

`run.sh` は `prompts/_shared-rules.md` ＋ 実行時コンテキスト（対象日・`config/meetings.json`）＋ 個別プロンプトを連結して `claude -p` に渡す。同じプロンプトの多重起動は `flock` で防いでいる。

必要なMCP：Notion / Slack / Google Calendar / Google Drive。

## 運用前に必要な設定

### 1. Slackチャンネル（設定済・ただし要確認）

| 会議体 | チャンネル | ID |
|---|---|---|
| 取締役週次定例 | `#04-mgmt-取締役` | `C0BH7S9QLKE` |
| 経営レイヤー定例 | `#04-mgmt_ボードと執行役員` | `C07QUGYPW7J` |

| 会議体 | カレンダー上の予定名 | 曜日・時刻 |
|---|---|---|
| 取締役週次定例 | **`取締役mtg`** | 月曜 10:00-11:00 JST（週次） |
| 経営レイヤー定例 | **`経営レイヤー定例mtg`** | 月曜 15:00-16:00 JST |

**カレンダー上の予定名は会議体の正式名称と一致しない。** 特に取締役側は「取締役mtg」で、「取締役週次定例」では1件もヒットしない。`config/meetings.json` の `calendar_title_keyword` はカレンダー上の実際の名前を入れること。

`crontab` は B-1 の2本（月曜12:00の本番と毎朝08:00のリトライ）を有効にしてある。パスは実際の配置に置き換えること。

雛形ページを「テンプレートとして保存」に登録する。B-1 / B-2 は既存ページに書き込むだけなので不要だが、A-1 / A-2 で必要になる。

## 議事録ページに書き込んでよい場所

ページの各欄には、誰がいつ埋めるかを表すマークが付いている。

| マーク | いつ | 誰が | 自動化の扱い |
|---|---|---|---|
| 🟩 | 会議前 | 各自 | 読み取り専用 |
| 🟦 | 会議中 | 進行役 | 一切書き込まない |
| 🤖 | 会議後 | 自動 | ここだけを書き込む |
| ⏺️ | 会議後 | 自動 | 文字起こしの原文と自動要約を加工せず格納する |
| 🟨 | 会議後 | オーナー（山口） | 対象外 |

決定内容・実行担当・期限は認識がずれやすく、AIが推測で埋めると誤った決定が一次情報として残る。そのため 🟦 は意図的に自動生成の対象外にしている。**初回テスト時は、🤖 と ⏺️ だけが埋まり 🟦 が空のままであることを必ず確認すること。**

## 雛形に加えた変更（2026-08-25）

取締役週次定例の雛形ページに、**🟦 会議中の仕分け（会議中／進行役が記入）** のトグルを追加した。会議で挙がった件を、進行役が会議中に2つに仕分ける。

| 表 | 列 | 行き先 |
|---|---|---|
| 執行役員連携事項 | 起案者 / 種別（共有・依頼・相談）/ 内容 | 次回の経営レイヤー定例のアジェンダ4へ転記される（処理Cの読み取り元） |
| 取締役課題 | 起案者 / 内容 / 次にどうするか | 取締役の中で持つ。**執行役員へは渡らない** |

執行役員連携事項の列は、経営レイヤー定例のアジェンダ4「取締役からの共有・依頼・相談」の 🟩 事前記入表と同じ形にしてある。処理C はここを1対1で転記すればよく、内容を組み立て直す必要がない。

**区分列を持つ1つの表ではなく、表を2つに分けた。** 1つの表に区分列を持たせると、行の読み違いがそのまま「渡すつもりのなかった件が執行役員に届く」になる。表が分かれていれば、処理C は片方の表しか読まないという書き方ができ、構造として取り違えようがない。

**この欄を足した理由。** 次回の経営レイヤー定例へ渡す提案の出どころが、これまで 🤖 5.上程（AI生成）か 🟩【経営課題の提起】（事前記入）しかなかった。どちらも「取締役がこの場で執行役員へ渡すと決めたもの」ではない。処理C はそれを執行役員の見える場所へ書き込むため、AIの推測が混ざると、決めていない提案が執行側に届く。会議中に進行役が書いたものだけを渡す形にして、そこを切った。

あわせて雛形側を3か所直した。

- ページ冒頭の流れの表に「当日（会議中）／進行役／🟦 のトグルで、挙がった件を執行役員連携事項と取締役課題に仕分ける」の行を追加
- 🟩【経営課題の提起】の説明を修正。「ここに書いた内容は次回の経営レイヤー定例で共有されます」→「ここに書いた内容の**うち、会議で「執行役員連携事項」に仕分けられたもの**が共有されます」。🟦 を経由するようになったため、元の文面のままだと嘘になる
- 🤖 5.上程 → 「5. 上程（候補）」に変更。AIが拾った候補であって確定ではなく、進行役が 🟦 への書き漏らしに気づくための控えである旨を明記

**処理C（A-2）の読み取り元は 🟩 ではなく 🟦「執行役員連携事項」の表になる。** 引き継ぎ書 §5-3 手順4 は「【経営課題の提起】この場で話したいこと」から抽出せよと書いているが、この変更で不要になった。「取締役課題」の表は読まない。A-2 の実装時に反映すること。

なお、雛形ページの中身を直しても、Notionの「テンプレートとして保存」に登録済みのテンプレートは自動では変わらない。登録済みのものがあれば、そちらも人が更新する必要がある。

## 経営レイヤー定例：雛形の新設とトグル化（2026-08-25）

**雛形ページを新設した。** `3c72fd3d-feaf-8132-886a-d605d12eebd3`（【雛形】YYYY-MM-DD 経営レイヤー定例）。2026-08-24 の回の構成をそのまま写し、中身を空にしたもの。引き継ぎ書に載っている `3c52fd3d-feaf-81ff-bbe9-fcd8cf668363` はゴミ箱にあるため使わない。A-2 はこの新しい雛形を複製元にする。

**サブ欄をトグル化した。** アジェンダ0〜4の 🟩 事前記入 と 🤖 議論の記録 を、トグル見出し（`### … {toggle="true"}`）にした。アジェンダ0〜6の並びは会議の進行順なのでそのまま残し、各アジェンダの中だけを畳めるようにしてある。マーク別にまとめる形は採らなかった。アジェンダの見出しが 🟩 側と 🤖 側の2か所に出てしまい、会議を上から進められなくなるため。

あわせて 0. の表を **「🟦 前回の持ち帰り（自動転記）」** に改名した。マークは 🟦 のままだが実際には A-2 が書き込む欄で、マークだけを見ると書き込み禁止の欄と区別がつかなかったため。取締役週次定例側の「前回の持ち帰り（自動転記）」と表記を揃えてある。**自動化が書き込んでよい 🟩 / 🟦 の欄は、見出しに「（自動転記）」が付いているかどうかで判断する。**（例外はアジェンダ4の 🟩 事前記入表だけ。人と処理Cが両方書く欄のため見出しを変えていない）

同じトグル化と改名を 2026-08-24 の実ページにも適用した。実データ（🟩 の事前記入、🟦 5.今日決まったこと、担当者メンション、コメントスレッド）はすべて保持している。トグル化は見出し行と `<table>` / `</table>` の行だけを触り、データ行は `old_str` に一切含めない方法で行った。Notionはトグル内の表を「開始タグと終了タグだけインデント、`<tr>` は非インデント」で出力するため、この2行だけで表をトグルの中へ移せる。

## 引き継ぎ書との差分

実装にあたって雛形ページを確認した結果、引き継ぎ書 §4 の記載と実物が食い違っていた箇所。

1. **文字起こしURLのプロパティ名は「Zoom録画」** — 引き継ぎ書は「文字起こし(URL)」としているが、両DBともZoom運用時代の名前が残っている。B-1 はMeetの文字起こしURLを `Zoom録画` に書く。Notion側で改名したら `prompts/board-weekly-minutes.md` の該当箇所も直すこと。
2. **取締役週次定例の雛形には3つ目のトグル ⏺️ がある** — 引き継ぎ書 §4-1 のページ構造は 🟩 と 🤖 の2つだけを挙げているが、実物には「⏺️ 文字起こしの原文・自動要約（会議後／自動生成）」がある。ページ冒頭の流れの表にも「🤖 と ⏺️ の中身が生成され」とあるため、B-1 の書き込み先に含めた。
3. **🟩 の見出しには後置きの説明が付く** — 実物は「【経営課題の提起】この場で話したいこと → 議題2で扱います」。処理C で見出しを目印に抽出するときは、この後置き部分を許容すること。
4. **取締役週次定例の雛形に 🟦 の欄がなかった** — 対処済み。下の「雛形に加えた変更」を参照。
5. **経営レイヤー定例の雛形ページがゴミ箱に入っている** — `3c52fd3d-feaf-81ff-bbe9-fcd8cf668363` は取得できるが `deleted` 状態。A-2 / B-2 の実装前に復元するか、作り直しが必要。あわせて、親DBの名前が「経営連携会議 議事録」のままになっている（data_source 側は「経営レイヤー定例 議事録」）。
6. **経営レイヤー定例の実ページの構成が、引き継ぎ書 §4-2 と違う** — 2026-08-24 の回（`3c52fd3d-feaf-80c3-8003-facb0fa002b9`）を見ると、🟦 の欄は「5. 今日決まったこと」だけになっており、§4-2 にある「6. 持ち帰り」「7. 決まらなかったもの」「8. 認識ギャップとして挙がったこと」がない。課題ボードの更新は 🟨 6.（§4-2 では 9.）。各見出しの所要時間（18分など）も落ちている。B-2 のSlack投稿は 🟦 欄を読み取って転記する仕様なので、**どの構成を正とするかを決めてから B-2 を実装する。**
7. **経営レイヤー定例のステータスに「自動生成済」がない** — 選択肢は `事前記入中` / `記録済` / `確認済` の3つ。引き継ぎ書 §5-4 手順4 は「自動生成済」にせよと書いているが、その値は存在しない。B-2 は `記録済` を使うことになる。取締役週次定例側は `事前記入中` / `自動生成済` / `確認済` / `要修正` で、2つのDBでステータスの語彙が揃っていない。
